## Problem Statement

The dashboard's roster/diff UI has drifted from the finalized v2 design reference (`.references/new-design/perm-diff.css` + the ledger mockups) in several concrete, checkable ways: wrong colors, missing chip/badge treatments, and control styling that reads as a different visual language than the approved design. One of these (the escalation-row sigil) is not just cosmetic — it silently makes an escalation ("~") indistinguishable from a plain level change, undermining the one signal an escalation audit exists to surface. An auditor comparing the live app to the design sign-off, or to a teammate's screenshot of the reference, sees a UI that doesn't match what was approved.

## Solution

Bring the components the v2 reference actually covers (head bar, filter bar, notice strip, roster rows, repo cards, project sections) back into pixel/color/token alignment with `perm-diff.css` and the ledger mockup, porting the specific missing design tokens each fix needs. Along the way, correct an inaccurate claim in ADR-0005 (it asserts the v2 redesign kept the roster-row meter as a text glyph; the actual v2 mockup renders it as 3 literal square segments) so the ADR and the code it governs stop contradicting each other. Do not expand scope to components the reference doesn't cover, or to functionality the reference implies but was never built (search/filter input, dark theme).

## User Stories

1. As an auditor scanning the roster, I want an escalation row's sigil to read "↑" (not "~"), so that an escalation is visually distinct from an ordinary level change at a glance.
2. As an auditor scanning the roster, I want each row's sigil rendered as a colored chip (matching its diff state), so that the "what changed" signal is legible without reading the row's other columns.
3. As an auditor, I want an unchanged ("same") row's sigil to render in a legible neutral ink rather than a near-invisible faint grey, so that idle rows are still scannable.
4. As an auditor, I want the per-row permission-level meter to render as 3 discrete filled/unfilled squares (matching the finalized design), so that the level channel is visually consistent with the rest of the design system's segmented-control language.
5. As an auditor, I want an escalation row's background tint to be the subtle wash the design specifies, not the stronger tint used for badges, so that escalation rows read as "flagged" without overpowering the rest of the roster.
6. As an auditor, I want a repo card's admin/write/read distribution bar to render as 3 separate colored segments with a visible gap between them (matching the reference), so that the split reads as discrete portions rather than a single smeared gradient.
7. As an auditor, I want the distribution bar's "write" segment to use the correct grey (not a darker one borrowed from body-text ink), so that its color matches the level-word text elsewhere on the same row.
8. As an auditor, I want a repo or project header's delta counts (+N/−N/~N/↑N) to render as filled color chips (not bare colored text), so that they're visually consistent with the identical-meaning chips in the head bar.
9. As an auditor, I want the "All access" / "Changes only" filter tabs to render as a soft grey track with a white "pressed" pill (matching the reference), so that the active tab reads as selected the same way it does in the approved design, not as a solid inverted button.
10. As an auditor, I want the notice strip's "STRUCTURAL" label to render as a solid badge pill (matching the reference), so that structural notices are as visually prominent as the design intends.
11. As an auditor, I want the notice strip's border to use the notice-specific edge color (not the generic rule color), so that its color language is consistent with its own background tint.
12. As a future maintainer, I want ADR-0005 to accurately describe what the v2 mockup does, so that I don't re-implement the wrong thing off a stale claim the next time I touch the roster row.
13. As a future maintainer, I want all of the above values to live as named tokens in `tokens.css` (not hardcoded hexes in component `<style>` blocks), so that the token sheet stays the single source of truth per its own header comment.
14. As an auditor, I want none of the above changes to alter the underlying diff/permission data or logic (only how it's rendered), so that the roster's correctness is unaffected by this pass.
15. As a maintainer, I want components with no corresponding v2 mockup (SideDrawer, CredentialsPanel, SnapshotsPanel, RunPanel, EmptyState) left untouched by this pass, so that no ad hoc, undocumented "corrections" are made without a reference to justify them.

## Implementation Decisions

- **`src/lib/styles/tokens.css`**: add `--track`, `--track-active`, `--shadow-segment`, `--r-row` (6px), `--segment-off`, `--seg` (9px), `--bar-admin`/`--bar-write`/`--bar-read`, `--escalation-row`, `--notice-badge`, `--notice-badge-ink`, `--h-sigil` (18px), `--h-chip` (20px). Values sourced from `perm-diff.css`'s light-theme `:root` block (the authoritative finalized stylesheet), not from the JS-prototype constants embedded in the `.dc.html` mockups, where the two sources' literal pixel values disagree (e.g. `perm-diff.css`'s segmented-tab height of 28px vs. the prototype's 26px) — `perm-diff.css` wins per its own status as the named "token sheet + component styles" (CLAUDE.md).
- **`docs/adr/0005-two-channel-visual-encoding.md`**: correct the sentence claiming v2 "kept this rule unchanged" for the meter's shape. The actual v2 mockup (`perm-diff-ledger-light.dc.html`) renders the meter as 3 literal square `<div>` segments (same technique as the distribution bar), not the `■■■`/`■■□`/`■□□` text glyph the ADR currently describes. The core rule the ADR protects (hue reserved for diff state, level carried by non-hue channels) is unaffected — only the *mechanism* description for one of those channels is being corrected.
- **`src/lib/rosterRow.ts`**: drop the `METER` glyph map and the `meter: string` field from `RosterRowView` — the meter's fill is now computed entirely by CSS, keyed off the already-existing `levelClass` (`lvl-admin`/`lvl-write`/`lvl-read`), via `nth-child` selectors mirroring `perm-diff.css`'s own `.meter--write span:nth-child(-n+2)` pattern. Fix the `LevelChange` case's `sigil` from a hardcoded `"~"` to `isEscalation ? "↑" : "~"`, matching the reference's `esc ? "↑" : "~"`.
- **`src/lib/components/RosterRow.svelte`**: meter markup becomes 3 empty `<span>`s inside the `.meter` wrapper, styled via the new nth-child rules using `--ink`/`--ink-2`/`--ink-4` (already present, and numerically identical to `perm-diff.css`'s `--level-admin/write/read`) for "on" and `--segment-off` for "off". Sigil becomes a fixed `--h-sigil` × `--h-sigil` chip with `border-radius: var(--r-chip)`, default color `--ink-3`, and a background/color pair per diff state (`--state-added`/`-bg`, `--state-revoked`/`-bg`, `--state-changed`/`-bg`, and `--escalation-bg`/`--escalation-ink` for the escalation modifier, applied after the `state-modified` rule so it wins). `.roster-row.escalation` background switches from `--escalation-bg` to the new `--escalation-row`.
- **`src/lib/repoCard.ts`**: replace `distributionBarBackground(repo): string` (a hand-built `linear-gradient` CSS string) with `distributionSplit(repo): { admin: number; write: number; read: number } | null` — returns per-segment percentages summing to 100, or `null` when the repo has zero grants (the zero-grants case is handled distinctly in the component, preserving the existing "flat `--rule-row` bar, not an empty element" behavior).
- **`src/lib/components/RepoCard.svelte`**: replace the single gradient-background `.bar` element with a `.dist` flex container (`gap: 2px`) holding 3 segments styled from `--bar-admin`/`--bar-write`/`--bar-read`, or a single flat `--rule-row` segment when `distributionSplit` returns `null`.
- **`src/lib/components/CountBadges.svelte`**: every `CountBadge` kind (`added`/`removed`/`modified`/`esc`/`none`) renders as a filled chip (`height: var(--h-chip)`, `border-radius: var(--r-chip)`, mono, weight 600) using the same `--state-*`/`--escalation-*` tokens already in `tokens.css` — not bare colored text as today, and not the current escalation-only bordered-tag treatment.
- **`src/lib/components/FilterBar.svelte`**: `.tabs` becomes a `padding: 2px; border-radius: var(--r-card); background: var(--track)` track; `.tab` loses its border/divider and becomes `border-radius: var(--r-row)`, `color: var(--ink-4)`; the active tab gets `background: var(--track-active); box-shadow: var(--shadow-segment); color: var(--ink)` instead of the current inverted solid `--ink` background. No change to the tab-switching interaction model (still a plain click handler, no ARIA tablist changes).
- **`src/lib/components/NoticeStrip.svelte`**: adds a `.badge` element ("structural") styled as a solid pill (`height: var(--h-tag)` — already 19px, matching the reference exactly — `background: var(--notice-badge)`, `color: var(--notice-badge-ink)`) rendered before the prose span. `border-bottom` color switches from the generic `--rule` to `--notice-edge`. The existing `box-shadow: inset 3px 0 0 var(--notice-edge)` left-gutter is removed (not present in the reference).
- No changes to any diff/permission computation, Rust backend, or data model — this is a rendering-only pass.

## Testing Decisions

- Only test external behavior of pure functions, not Svelte markup/CSS (per ADR-0017, Svelte component rendering has no automated seam in this repo — Playwright is an intentionally-unused, deferred dependency).
- `src/lib/rosterRow.test.ts` (existing suite, extend in place): assert `deriveRow` returns `sigil: "↑"` for an Escalation `LevelChange` and `sigil: "~"` for a non-escalation `LevelChange`/Demotion, closing the gap the existing tests didn't cover.
- `src/lib/repoCard.test.ts` (existing suite, extend in place): assert `distributionSplit` returns the correct admin/write/read percentages for a mixed-grant repo, and `null` for a zero-grant repo. Replaces any prior expectations tied to the removed `distributionBarBackground`.
- Everything else in scope (token additions, sigil chip styling, meter segment CSS, escalation-row tint, CountBadges chip styling, FilterBar segmented-control restyle, NoticeStrip badge) is CSS/markup-only in `.svelte` files and has no automated render-test seam available under the current architecture (ADR-0017) — verified manually via `pnpm dev` / `pnpm tauri dev`, comparing against `.references/new-design/perm-diff-ledger-light.html` and `-dark.html` (light theme only, since dark theme isn't ported).
- `pnpm check` (svelte-check) must pass after all changes.

## Out of Scope

- Dark theme: no CSS values ported, no toggle control built. `tokens.css` already flags this as pending re-port; unrelated to this pass.
- The reference's "Filter users, groups or repos…" search input: no UI element or filtering logic exists for it anywhere in the app today (`filterBar.ts` has no such logic). Building it is new functionality, not a style fix, and is left for its own ticket.
- Components with no v2 mockup counterpart: `SideDrawer.svelte`, `CredentialsPanel.svelte`, `SnapshotsPanel.svelte`, `RunPanel.svelte`, `EmptyState.svelte`. No reference exists to diff them against.
- Any diff/permission computation, Bitbucket fetch logic, storage, or Rust backend code — this is frontend rendering only.
- Adding Playwright or any other visual-regression tooling — remains deferred per ADR-0017.
- Head bar (`HeadBar.svelte`): PD-41's claim that this "already matches the reference exactly" turned out to be inaccurate — a follow-up `/grill-with-docs` session found real mismatches (Run-selector styling, wordmark layout, ink tokens, control sizing, cluster spacing). Tracked separately as PD-51, not folded into this ticket's scope.

## Further Notes

This spec was produced by a `/grill-with-docs` review session that read `perm-diff.css`, the decompressed `perm-diff-ledger-light.dc.html`/`perm-diff-ledger-dark.dc.html` mockups (which contain literal computed values per component state, not just class names), `tokens.css`, and every in-scope Svelte component's `<style>` block, cross-referencing each against ADR-0005 through ADR-0017. The ADR-0005 contradiction (claimed vs. actual v2 meter shape) was surfaced during that cross-reference and confirmed with the user as a genuine inaccuracy worth correcting, not a deliberate deviation. All scope and technique decisions above (segment-vs-gradient, ADR-vs-mockup authority, which components are in/out of scope) were explicitly confirmed with the user one at a time before this spec was written; nothing here is a fresh proposal.
