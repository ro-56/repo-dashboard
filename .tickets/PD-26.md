## What to build

Add a snapshot list sub-panel to the side drawer (alongside credentials and the run trigger), listing every Snapshot with a delete action per row, wired to `delete_snapshot` (PD-25). Deletion requires a confirmation step — it's the one irreversible action in the app's diff model.

Per ADR-0011: if the deleted Snapshot was part of the current Baseline/Comparison selection, the dashboard falls back to the latest-vs-previous pair — the same rule used after a new run (PD-24), rather than erroring or showing a broken selection.

## Acceptance criteria

- [ ] Drawer lists all snapshots (id/timestamp, matching the head bar selector's existing run-numbering scheme in `headBar.ts`)
- [ ] Each row has a delete action that requires explicit confirmation before calling `delete_snapshot`
- [ ] After deletion, the snapshot list refreshes and no longer shows the deleted snapshot
- [ ] If the deleted snapshot was the current Baseline or Comparison, selection falls back to latest-vs-previous (same behavior as PD-24's post-run jump)
- [ ] If the deleted snapshot was not part of the current selection, the current Baseline/Comparison selection is left untouched
- [ ] Deleting down to zero snapshots shows the same empty/first-run state used when no snapshot has ever been taken
