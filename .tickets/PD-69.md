## What to build

Extract the per-repo and per-project fetch+normalize+membership-resolution logic currently inlined in the Run loop (`collect_and_store`) into two standalone, reusable async functions — one for a single repo's Direct+Group permissions, one for a single Project's Direct+Group permissions — each still using the existing normalize functions and the existing membership-caching pattern, but callable independently of the Run's repo-discovery loop.

The upcoming Refresh feature (PD-68) needs to invoke this exact logic for an explicit, narrow list of repos/projects rather than every discovered repo — duplicating the intricate cache/error-handling logic would be a maintenance risk. This ticket is a pure refactor: no behavior change to `collect_and_store`'s output.

## Acceptance criteria

- [ ] The per-repo Direct+Group fetch (including per-group membership resolution and its cache) is extracted into a standalone async function, callable with just a client, workspace, and a single repo — no dependency on the Run's overall loop state.
- [ ] The per-project Direct+Group fetch (including its own membership cache) is extracted into a standalone async function, callable with just a client, workspace, and a single project key — no dependency on any specific repo or the Run's overall loop state.
- [ ] `collect_and_store` is rewritten to call these two new functions instead of inlining the logic; its own membership cache is threaded through unchanged (still one `list_group_members` call per group id per Run, not per function call).
- [ ] The existing `cargo test` suite for the collection module passes unchanged — same assertions, same behavior, for every existing test case (discovery failure, per-repo fetch failure, project fetch failure, group membership resolution, caching).
- [ ] The extracted functions are structured such that Refresh's own tests (next ticket) can call them directly against a fake client.
