## What to build

Two related, already-decided additions to the roster UI (ADR-0014, ADR-0012):

(a) `sourceLabel()` (`rosterRow.ts`) takes the entry's `scope` (Repo/Project) as an additional input and appends `" · project"` to the source cell text when scope is Project-level — no suffix for Repo-level (today's default rendering). The row's existing tooltip continues to carry the full unabbreviated text.

(b) Add `projectFetchFailed: boolean` to the `RepoNode` TypeScript interface (`roster.ts`) — mirroring the field Rust's roster tree already computes and serializes — and have `repoCard.ts`'s tag derivation add a `project fetch failed` tag on any repo where it's true, visually and textually distinct from the existing repo-level `fetch failed` tag (both can appear together). No change to the structural notice strip — this is a per-repo-card tag only, no new notice sentence.

## Acceptance criteria

- [ ] A Project-level grant's source cell reads e.g. `direct · project` / `group · project` / `grp:<name> · project`; a Repo-level grant's source cell is unchanged
- [ ] The source cell's tooltip shows the full scope-qualified text even when the cell itself is truncated
- [ ] `RepoNode` TS interface includes `projectFetchFailed: boolean`
- [ ] A repo with `projectFetchFailed: true` shows a `project fetch failed` tag on its card header, distinguishable from the `fetch failed` tag, and both can render simultaneously
- [ ] No sentence added to the structural notice strip for Project fetch failures
- [ ] `pnpm check` passes
- [ ] Verified via `pnpm tauri dev` against fixture data covering: a Repo-level grant, a Project-level Direct/Group/Member grant, and a repo with `projectFetchFailed` true (with and without its own `fetchFailed` also true)
