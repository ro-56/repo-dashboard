## What to build

Add a "get all data" (Run now) button to the side drawer, wired to the existing `run_now` command.

Per ADR-0010: on a successful run, the dashboard's Baseline/Comparison selection always jumps to the new latest-vs-previous pair — even if the user had manually pinned two specific historical snapshots beforehand. This is a deliberate simplicity trade-off (see the ADR); don't try to preserve a manual pin across a run.

## Acceptance criteria

- [ ] Drawer has a "get all data" button that calls `run_now`
- [ ] While a run is in progress, the button shows a running/disabled state (matches the old `/` page's `running` behavior)
- [ ] On success, the snapshot list refreshes and Baseline/Comparison selection updates to the new latest-vs-previous pair, regardless of what was previously selected
- [ ] On failure, the error is surfaced in the drawer (matches the old `/` page's error surfacing, e.g. "credential rejected", "could not reach Bitbucket")
