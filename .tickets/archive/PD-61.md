## What to build

Widen PD-60's Direct-grant editing mechanism to Project scope. No new interaction machinery — the pendingEdits state, confirm dialog, Apply control, and gating/clearing behavior from PD-60 are reused unchanged; this ticket only adds the missing scope dimension.

- **`BitbucketClient`**: add project-scope Direct-grant write methods — set (`PUT /2.0/workspaces/{workspace}/projects/{project_key}/permissions-config/users/{selected_user_id}`) and delete (`DELETE` same path). Requires `project:admin` scope on the credential (no proactive check — ADR-0023; a 403 surfaces as a normal per-item apply failure).
- **`apply_pending_edits`**: extend routing so a `PendingEditRequest` with `scope: Project, target: Direct(...)` reaches the new client methods.
- **`rosterRow.ts`**: the existing Direct-entry menu function now also applies to Project-scope rows, reusing the existing "Project-level grant — applies to all N repos it owns" cascade note already shown elsewhere in the dashboard (no new note needed).

## Acceptance criteria

- [ ] A Direct grant row at Project scope shows the same menu (Read/Write/Admin + Remove) as Repo-scope rows.
- [ ] Opening the menu on a Project-scope row shows the existing "applies to all N repos" note.
- [ ] Staging, undo, batching, confirm dialog, Apply, and per-item results all work identically for Project-scope Direct edits as they do for Repo-scope ones (no duplicated state machinery).
- [ ] A successful apply calls Bitbucket's real project-level user permissions-config endpoint (set or delete as appropriate).
- [ ] A batch mixing Repo-scope and Project-scope Direct edits applies each independently and reports per-item results.
- [ ] `cargo test` covers `apply_pending_edits`'s Project/Direct routing (set, delete) against a fake `BitbucketClient`.
- [ ] Colocated `rosterRow.test.ts` additions cover the Direct-entry menu appearing correctly for Project-scope entries with the cascade note.
- [ ] Manually verified via `pnpm tauri dev` that a Project-scope edit, once applied and re-run, is reflected in the roster.
