## What to build

A togglable visual emphasis on Escalation-type Level-changes specifically (prototype's `highlight-escalations`), distinct from generic diff markers — PRD §5.4. Toggle state is UI-only (no persistence requirement stated in PRD); Demotions and Grants/Revokes are unaffected by the toggle.

## Acceptance criteria

- [ ] A visible toggle control turns escalation highlighting on/off.
- [ ] When on, Escalation markers get additional visual emphasis (per prototype) beyond their normal diff-marker rendering from PD-12; Demotions/Grants/Revokes look the same regardless of toggle state.
- [ ] Toggle state persists across expand/collapse and across changing the Run pair within the same session (survives re-fetching the tree for a new Run pair), but does not need to survive an app restart.

## Out of Scope

- Changes-only filter, empty/no-changes states — next ticket.
## Notes

Superseded by ADR-0007: escalation highlighting is always on, with no toggle. The reference design exposes highlightEscalations as a component prop defaulting to true and has no such control in its toolbar; the token sheet justifies the always-on amber wash as what makes escalations findable by eye with no filter applied. PRD 5.4's 'togglable' wording is superseded. The always-on rendering is built in PD-15.
