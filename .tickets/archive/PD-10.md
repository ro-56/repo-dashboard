## What to build

The first tracer bullet through the roster/diff dashboard (PRD §5.4): a Tauri command that loads a Run pair's two Snapshots, computes the Roster tree (project → repo → Principal, diff markers attached — even when Run A = Run B, in which case it's a pure roster with no markers), per ADR-0004 (`docs/adr/0004-roster-tree-computed-per-request.md`); a `list_snapshots` command for populating the two run selectors; and a SvelteKit route reading `snapshot_a`/`snapshot_b` from URL query params (defaulting both to the latest Snapshot) that renders prototype state `1b` — all project sections and repo cards collapsed, each summarizing access-level distribution (read/write/admin counts) and a change count (zero when Run A = Run B).

## Acceptance criteria

- [ ] `list_snapshots` Tauri command returns every Snapshot's id + run_at, newest first.
- [ ] `get_roster_tree(snapshot_a_id, snapshot_b_id)` Rust function (the test seam) loads both Snapshots via PD-6's `load_snapshot`, runs the existing diff engine unmodified, and returns a project → repo → Principal tree with each Principal's diff status (none/grant/revoke/level-change) and each repo's fetch-status/absence flag attached.
- [ ] Selecting the same Snapshot for both A and B returns a tree with zero diff markers — a pure roster, not an error or empty result.
- [ ] SvelteKit route (e.g. `/dashboard`) reads `snapshot_a`/`snapshot_b` from URL query params; omitted params default to the two most recent Snapshots (or the single most recent one, twice, if only one Snapshot exists).
- [ ] Renders prototype state `1b`: every project section and repo card visible, all collapsed, each card showing its read/write/admin counts and change count.
- [ ] Repo grouping/sorting logic lives in Rust and is covered by `cargo test`; the Svelte layer only renders the tree it's given.
- [ ] `cargo test` covers: a two-Snapshot Run pair with a mix of grants/revokes/level-changes producing the correct tree; an identical-Snapshot Run pair producing zero diff markers; a repo absent from one Snapshot's discovery flagged at the repo level.

## Out of Scope

- Expand/collapse interaction, full member roster — next ticket.
- Diff markers rendered in the UI (only collapsed-card counts render this ticket) — the tree carries the data already, the UI catches up next ticket.
- Escalation-highlighting toggle, changes-only filter — later tickets.
- Execution-history page routing into this URL shape — that page doesn't exist yet; this ticket just makes the URL contract exist first.
