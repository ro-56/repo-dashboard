## What to build

Extract every hardcoded English string in the core audit view into the i18n catalog (en + pt-BR), including the strings introduced by the recent tooltip-copy-draft work:

- `RosterRow.svelte` / `rosterRow.ts`: row sigil tooltips (same/added/removed/escalation/other), row meter text, row tags (esc/unresolved/pending-level/pending-remove)
- `RepoCard.svelte` / `repoCard.ts`: bar-cell distribution text, repo tags (gone/new/failed/project-failed)
- `RosterColumnLabels.svelte`: column header tooltips (±, lvl, access, source, etc.)
- `CountBadges.svelte`: count badge tooltips (added/removed/modified/esc/none)
- `ProjectSection.svelte`: any project-grouping label strings

Domain vocabulary (Grant, Revoke, Escalation, Demotion, Level change, Direct/Group/Member, etc.) is translated per CONTEXT.md's "Display language" term, not left in English. Bitbucket-sourced content (repo/Project names, Principal labels) stays untouched/verbatim — this ticket never touches that data path.

## Acceptance criteria

- [ ] No hardcoded English string literals remain in the five components/modules listed above (all route through the i18n catalog)
- [ ] Every key has both an English and a reviewed pt-BR translation
- [ ] Domain vocabulary terms render translated in pt-BR, not left as English loanwords
- [ ] Repo/Project/Principal names still render verbatim regardless of Display language
- [ ] Manually verified via `pnpm tauri dev`: switching Display language re-renders the whole roster tree (rows, tags, tooltips, count badges) in the selected language with no leftover English strings
