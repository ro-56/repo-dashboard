## What to build

Per ADR-0011 (`docs/adr/0011-snapshots-are-deletable.md`): add a `delete_snapshot(id)` Tauri command that permanently deletes a Snapshot and cascades to its `PermissionRecord` rows (and any per-repo fetch-status rows scoped to that snapshot).

This reverses PRD §5.3/§5.5's original "keep everything indefinitely, no delete in v1" — the ADR records why. Note this doesn't change the `Snapshot` glossary entry's "immutable" meaning (content is still never edited in place); see the updated entry in `CONTEXT.md`.

Backend-only slice, independent of the drawer UI work — verify via `cargo test`.

## Acceptance criteria

- [ ] `delete_snapshot(id)` removes the Snapshot row and all `PermissionRecord` rows for that `snapshot_id`
- [ ] Any per-repo fetch-status data scoped to that snapshot is also removed
- [ ] Deleting a non-existent snapshot id returns a clear error, not a silent no-op
- [ ] `cargo test` covers: delete removes all associated rows; `list_snapshots` no longer includes the deleted snapshot; deleting an unknown id errors

Added delete_snapshot(id) Tauri command + storage::delete_snapshot: cascades permission_records, repo_fetch_statuses, and group_membership_statuses in one transaction, errors clearly on unknown id. Covered by 3 new cargo tests.
