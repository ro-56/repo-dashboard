## What to build

A transient Principal search text input in the Roster view's FilterBar, narrowing the visible tree to repos containing at least one Principal (Direct, Group, or Member grant alike) whose label matches the typed text.

- Case-insensitive substring match against a Principal's label only (not id, not repo/project name).
- AND-combines with the existing All access / Changes only view mode — a repo must satisfy both to stay visible.
- A repo with no matching Principal disappears from the tree entirely (same mechanism as the existing Changes-only repo-level filtering); a Project section with zero visible repos disappears entirely too.
- The "N live · N changed · N rows" count note reflects only entries within repos currently passing both the view-mode and search predicates — it must never disagree with what's drawn.
- Search text persists across Baseline/Comparison navigation (does not reset when the Run pair changes), but is cleared by the existing Reset control alongside view mode and expand/collapse state.
- Search text is never persisted beyond the current session — no storage across app restarts.
- Zero matches anywhere in the tree shows the existing generic "no matches" empty state.
- The CSV Roster Export and the workspace-wide summary figures (comparison/pair stats shown elsewhere in the dashboard) remain unaffected by an active search — they keep describing the whole audited workspace regardless of what's currently filtered on screen.

Out of scope for this ticket: auto-expanding a search-matched repo by default (tracked separately), and the "exclude a Principal" reverse filter (a distinct future feature).

## Acceptance criteria

- [ ] A search input exists in the FilterBar and drives a session-only search query as the user types.
- [ ] Matching is case-insensitive substring against a Principal's label, checked across Direct/Group/Member entries in a repo.
- [ ] Repo visibility ANDs the search predicate with the active view mode (All access / Changes only).
- [ ] A repo with no match disappears from the tree; a Project section with zero remaining visible repos disappears too.
- [ ] The count note only counts entries in currently-visible repos under both predicates.
- [ ] The search query persists across Baseline/Comparison navigation.
- [ ] The existing Reset control clears the search query in addition to its current behavior (view mode, expand/collapse state).
- [ ] Zero matches anywhere shows the existing "no matches" empty state.
- [ ] Colocated unit tests cover: match/no-match against Direct/Group/Member entries, AND-combination with both view modes, and count-note accuracy against a narrowed tree.
- [ ] CSV Export output and workspace-wide summary figures are verified unchanged with an active search.
- [ ] Manually verified via `pnpm tauri dev`.
