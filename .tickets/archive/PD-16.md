## What to build

The frame around the roster: repo cards, project sections, the single column-label strip, and the rule that decides what is open when the screen first paints.

Replaces the current `auto-fill minmax(220px, 1fr)` card grid with the reference's full-width stacked cards. Cards are 2px radius, `--rule` bordered, on the `--canvas` (#eef0f2) background, 3px apart.

## Acceptance criteria

- [ ] A repo card header renders on the grid `caret | project/repo | distribution bar | grants text | counts | tag` at `--card-h` (22px), with `--surface` when collapsed and `--surface-raised` when open.
- [ ] The repo path renders as `project/` in `--ink-mute` followed by the repo name in weight 600 — one string, two weights.
- [ ] The distribution bar is a 58×6px three-stop grey gradient (#14181c / #5b656d / #b9c0c6) showing the admin/write/read split **of grants**, per ADR-0008. A repo with zero grants renders a flat `--rule-row` bar, not an empty element.
- [ ] Card and project counts render as `+n`, `−n`, `~n` in their state hues, plus `↑n esc` in the escalation tag style when escalations exist. A card with no changes reads `no change` in `--ink-faint`, not a blank space or a zero.
- [ ] Card header text reads in grants, never headcount — `"7 grants · 2 admin"`, per ADR-0008.
- [ ] A repo absent from one side of the Run pair strikes through its path, colours the repo name `#9e2b20`, and carries an `absent from run N` tag. A repo present only in the Comparison carries `new in run N`. Both use the `--tag-gone` / `--tag-new` styles.
- [ ] A project section renders a header with the project name in mono 600, meta (`3 repositories · 12 people`), a 2px `--ink` bottom rule, and rolled-up counts across its repos.
- [ ] The column-label strip (`± lvl access source user since baseline notes`) renders **once** above the canvas, not per card.
- [ ] Default expand: repos with at least one change open automatically; repos with no changes stay collapsed. If the Run pair has no changes anywhere, every card opens.
- [ ] Expanding and collapsing a card by clicking its header still works, and the caret reflects state (`▼` / `▶`).

## Out of Scope

- Expand all / Collapse all / Reset controls — PD-20.
- The `fetch failed` tag and unresolvable-membership rendering — PD-19.
- Summary bar and head bar — PD-18.
- Repo arrival (`new in run N`) depends on data PD-17 adds; until PD-17 lands, build the rendering and drive it from repo-absence data only.

## Further Notes

The default-expand rule is a deliberate change to PD-11's shipped collapsed-by-default behaviour, agreed in the design session. PRD §5.4's all-collapsed overview (state `1b`) is preserved separately as the Collapse all control in PD-20.
