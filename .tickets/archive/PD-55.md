## Problem Statement

`SideDrawer.svelte` and its three child panels (`CredentialsPanel`, `RunPanel`, `SnapshotsPanel`) were ported from an earlier revision of the v2 design and have drifted from the finalized reference (`.references/new-design/Ledger Light.dc.html`, backed by `.references/new-design/perm-diff.css`). Separately, the drawer's `appearance` section — a persisted light/dark theme toggle — was decided in ADR-0016 and scoped as its own ticket (PD-39) but was never implemented, so `tokens.css` still has only a light palette and the drawer has no fourth section at all. Both gaps live in the same component tree and were surfaced together in a `/grill-with-docs` session cross-referencing the shipped drawer against the reference.

## Solution

Resync the drawer's existing three sections (credentials/run/snapshots) to the exact values in `perm-diff.css`'s `.drawer`/`.panel`/`.snapshot-*` classes, and add the fourth `appearance` section with a persisted light/dark toggle, folding in PD-39's full scope (dark `tokens.css` block, `theme.ts`, toggle UI) as one pass since both are driven by the same reference file and touch the same component tree. This supersedes PD-39 — PD-39's scope is fully absorbed here and should be closed once this ticket lands.

`perm-diff.css` is the ground truth for exact values, not the `.dc.html` mockup's inlined styles — the mockup is a rendered instance and drifts slightly (e.g. its drawer-body padding reads `18px 16px` where the actual `.drawer-body` class is `var(--s-8) var(--s-7)`, i.e. 18px/14px). Where the mockup and the stylesheet disagree, the stylesheet wins.

## User Stories

1. As an auditor, I want the drawer's "settings" title to use the same 0.14em letter-spacing as every other 10px uppercase label in the app (head bar wordmark subtitle, baseline/comparison labels), so that the drawer doesn't look visually inconsistent with the rest of the chrome.
2. As an auditor, I want the open drawer to cast a soft shadow (`-8px 0 20px rgba(20,24,28,.08)` in light, `rgba(0,0,0,.45)` in dark) separating it from the dashboard behind it, so that it reads as a panel floating above the content rather than flush with it.
3. As an auditor, I want the drawer's background to match the head bar's pure white rather than the slightly-off-white used for open repo-card headers, so that the drawer's surface color is correct per the reference (`--surface-head` maps to `--surface`, not `--surface-raised`).
4. As an auditor, I want every button inside the drawer (close, save/cancel credentials, run now, snapshot delete/confirm/cancel) to use the same 6px corner radius already used by `FilterBar`'s and `HeadBar`'s controls, so that the drawer's buttons don't look sharper/more clipped than the rest of the app's controls.
5. As an auditor, I want the vertical gap between a panel's title and its content to match the reference's tighter 10px spacing, and the gap between a snapshot row's Delete/Confirm/Cancel buttons to match its tighter 6px spacing, so that the drawer's density matches the finalized design.
6. As a user, I want a light/dark theme toggle inside the side drawer (alongside credentials/Run/snapshot management), so that I can switch themes from the same place I manage other app-level settings.
7. As a user, I want my theme choice to persist across app launches, so that I don't have to re-select it every time I open the app.
8. As a first-time user who has never set a theme preference, I want the app to default to my OS's light/dark preference (`prefers-color-scheme`), so that the app matches my system out of the box.
9. As a user switching themes mid-session, I want the switch to apply immediately across the whole dashboard without a reload, so that the toggle feels responsive.
10. As a user with the dark theme active, I want every component (head bar, filter bar, roster rows, repo cards, tags, chips, side drawer) to render with dark-theme-correct colors, so that nothing looks broken or mismatched when I switch themes.
11. As a developer, I want the toggle itself styled as a segmented pill control (active side white with a soft shadow, inactive side transparent), reusing the same `--track`/`--track-active`/`--shadow-segment` tokens `FilterBar`'s segmented control already uses, so that the app doesn't grow a second visual pattern for the same interaction.
12. As a developer, I want `theme.ts`'s OS-preference fallback read once at initialization (not a live `matchMedia` listener), matching PD-39's original wording, so that a user who has an explicit stored choice is never silently overridden by an OS-level change mid-session.

## Implementation Decisions

- **Scope**: `SideDrawer.svelte`, `CredentialsPanel.svelte`, `RunPanel.svelte`, `SnapshotsPanel.svelte`, `tokens.css` (dark block addition), and a new `theme.ts` module. No other component's markup changes, though every component's *rendered colors* change once the dark block exists, since they already consume `tokens.css` custom properties by name with no hardcoded hex (verified: none exist in `src/lib/components` today).
- **Drawer chrome fixes** (from `.drawer`/`.drawer-head`/`.drawer-title`/`.drawer-close` in `perm-diff.css`):
  - `.drawer` gains `box-shadow: -8px 0 20px rgba(20,24,28,.08)` (light) / `rgba(0,0,0,.45)` (dark) — tokenized as a new `--shadow-drawer` custom property in both `tokens.css` theme blocks, following the existing precedent of `--shadow-card`/`--shadow-segment` being theme-varying tokens rather than hardcoded per-component values.
  - `.drawer`'s background changes from `var(--surface-raised)` to `var(--surface)`.
  - `.drawer` z-index moves from `10` to `40`, keeping it above the roster row's "⋯" context menu (currently no explicit z-index; reference uses `30` for that menu — no change needed there since default stacking already resolves correctly, but the drawer's value is aligned to the reference for headroom).
  - `.drawer-title` letter-spacing changes from `0.09em` to `0.14em`.
  - `.close` (drawer) and every button in `CredentialsPanel`/`RunPanel`/`SnapshotsPanel` change `border-radius` from `var(--radius)` (2px) to `var(--r-row)` (6px) — `--r-row` already exists in `tokens.css` and is already used correctly by `FilterBar`/`HeadBar`. `EmptyState.svelte` has the same `var(--radius)` button pattern but is out of scope (unrelated component).
- **Panel spacing fixes** (from `.panel`/`.snapshot-row__actions` in `perm-diff.css`): each panel's title-to-content gap changes from `var(--s-6)` (12px) to `var(--s-5)` (10px); `SnapshotsPanel`'s per-row action-button gap changes from `var(--s-5)` (10px) to `var(--s-3)` (6px). `drawer-body` padding, `.panel + .panel` margin/padding-top, and `.snapshot-list`/`.snapshot-row` gaps are already correct — no change.
- **Dark theme token port** (`tokens.css`): add a `:root[data-theme="dark"]` block with every dark value from `perm-diff.css`'s dark block (lines 131-192), mapped onto the *same custom property names* `tokens.css` already uses for light (the PD-36 name mapping — e.g. `perm-diff.css`'s `--surface-card-open` is `tokens.css`'s `--surface-raised`), not `perm-diff.css`'s literal names. Where `perm-diff.css` has a token `tokens.css` doesn't (e.g. `--rule-strong`, `--rule-card`, `--notice-*` — the latter now unused since the notice strip was removed per PD-52), only port the ones with a live consumer in `tokens.css` today.
- **`theme.ts`** (new pure-TS module): exposes current theme (`"light" | "dark"`), a setter, and an init function that reads `localStorage`, falling back to a one-time read of `window.matchMedia("(prefers-color-scheme: dark)")` when no stored preference exists. The setter persists to `localStorage` and applies the theme by setting `data-theme` on the root `<html>` element, so the switch is instant and CSS-only with no per-component JS branching.
- **`SideDrawer.svelte` — new `appearance` section**: fourth panel, same `.panel`/`.panel + .panel` structure as credentials/run/snapshots. Contains a two-segment Light/Dark pill control mirroring `FilterBar`'s existing segmented-control CSS pattern (`--track` background track, active segment gets `--track-active` background + `--shadow-segment`, inactive segment transparent).
- **Bookkeeping**: PD-39 ("Feature: dark theme tokens + persisted toggle in side drawer") is fully superseded by this ticket and should be closed as a duplicate once this lands.

## Testing Decisions

- `theme.ts` gets colocated `theme.test.ts` (ADR-0017 convention, same pattern as `rosterRow.test.ts`/`repoCard.test.ts`): cover localStorage read/write, the `prefers-color-scheme` fallback when no stored value exists, and that an explicit stored choice is never overridden by a later OS-preference change (no live listener).
- Everything else — the drawer/panel CSS value changes, the new `appearance` section's markup, and the toggle's visual behavior — is manually verified via `pnpm tauri dev`, per this repo's established convention for Svelte/CSS changes (`CLAUDE.md`, ADR-0017).
- Manual verification should specifically exercise: the toggle switching instantly with no reload in both directions, persistence across a relaunch, first-launch behavior with no stored preference (matches OS setting), every drawer button's corner radius and the drawer's shadow/z-index (opens above an open row's "⋯" menu), and a full pass over head bar/filter bar/roster rows/repo cards/tags/chips in dark mode to confirm no color looks wrong.
- `pnpm check` (svelte-check/TypeScript) must pass.

## Out of Scope

- `EmptyState.svelte`'s identical `border-radius: var(--radius)` button bug — unrelated component, not part of the side drawer.
- A live `matchMedia` change-event listener that would update the theme in response to an OS-level change while the app is running with no stored preference — explicitly rejected per PD-39's original wording (init read only).
- Any change to `CredentialsPanel`/`RunPanel`/`SnapshotsPanel`'s functional behavior — this pass is chrome/spacing/token fixes only, no logic changes.
- Any new domain concept or `CONTEXT.md` glossary change — presentation-layer only.
- Porting `perm-diff.css` tokens with no live consumer in `tokens.css` (e.g. `--rule-strong`, `--rule-card`, `--notice-*`).

## Further Notes
