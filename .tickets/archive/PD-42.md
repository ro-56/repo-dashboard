## What to build

Wire up `vitest` as the frontend's unit test runner, per ADR-0017 (`docs/adr/0017-vitest-for-agent-feedback-defer-playwright.md`). This reverses PD-31/32/33/34's standing 'no JS test runner, manual `pnpm tauri dev` verification' convention — not because manual verification was wrong for a human, but because an AI agent modifying the UI needs a fast, deterministic signal it can act on mid-edit without launching the full desktop shell.

## Implementation Decisions

- **Tooling**: `vitest`, since it shares Vite's existing config/transform pipeline (no second bundler to maintain).
- **Scope**: pure-TS logic modules only — `roster.ts`, `rosterRow.ts`, `repoCard.ts`, `headBar.ts`, `filterBar.ts`, `noticeStrip.ts`, `emptyState.ts`. Svelte component rendering and E2E/visual testing (Playwright) are explicitly out of scope — deferred per the same ADR.
- **Coverage is incremental, not backfilled**: this ticket adds the tooling, a `pnpm test` script, and a first test file for whichever module it touches (or a minimal smoke test if it touches none directly). Every module listed above does NOT need a test written in this ticket — coverage accrues the next time a ticket touches a given module, mirroring how `cargo test` coverage grew ticket-by-ticket on the Rust side.
- **Test file convention**: colocated `*.test.ts` beside the module it covers (e.g. `rosterRow.test.ts` next to `rosterRow.ts`), matching the Rust convention of test modules living alongside the code they test.
- **Docs**: update `CLAUDE.md`'s Commands section (add `pnpm test`) and replace its 'no JS test runner configured yet' line to describe the new incremental convention and cite ADR-0017.

## Acceptance Criteria

- [ ] `vitest` is a devDependency; `pnpm test` runs it once and exits (CI-style), a `pnpm test:watch` (or equivalent) runs it in watch mode.
- [ ] At least one pure-TS module has a colocated `*.test.ts` demonstrating the convention.
- [ ] `CLAUDE.md` reflects the new convention and no longer states 'no JS test runner configured.'
- [ ] `pnpm check` still passes.

## Out of Scope

- Backfilling tests for every existing pure-TS module.
- Svelte component tests, Playwright/E2E setup, or the Tauri `invoke()` mock shim — all deferred per ADR-0017.
- Any `src-tauri`/`cargo test` changes.
