## What to build

Per PD-53, replace the roster's Project-scope text suffix (`· project`, ADR-0014) with a monochrome prefix glyph on the grant-source label. `sourceLabel()` should prepend `↳ ` (U+21B3) to the base label when a grant is Project-scoped (`↳ direct`, `↳ grp:secops`), instead of appending `· project`. Repo-scoped output is unchanged. The row component's tooltip for Project-scoped rows changes from echoing the visible text back to a short explanatory string ("↳ Project-level grant"); Repo-scoped tooltip behavior is unchanged. Write a new ADR recording this decision and mark ADR-0014 as superseded by it.

## Acceptance criteria

- [ ] Project-scoped grants render as `↳ <base label>` (prefix, single space) instead of `<base label> · project`
- [ ] Repo-scoped grants render exactly as before — no prefix, no visual change
- [ ] The glyph inherits `.source`'s existing ink color (`--ink-3`) — no new CSS custom property, no independent hue
- [ ] Project-scoped rows' tooltip reads as a short explanatory string ("Project-level grant"), not an echo of the visible label
- [ ] Repo-scoped rows' tooltip behavior is unchanged
- [ ] `rosterRow.test.ts`'s existing `sourceLabel` cases are updated from the `· project` suffix format to the `↳` prefix format
- [ ] New test coverage exists for the tooltip string, for both Project- and Repo-scoped entries
- [ ] `pnpm test` and `pnpm check` pass
- [ ] A new ADR is written recording the glyph decision (truncation problem, ADR-0005 hue constraint, why `.source` over `.tags`, why U+21B3 over U+2934); ADR-0014's status is updated to superseded by it
- [ ] Verified visually via `pnpm tauri dev`: glyph renders cleanly next to `IBM Plex Mono` text, no font-fallback mismatch, tooltip shows on hover
