## What to build

Surface the `run-progress` event (emitted by `run_now`, PD-32) in `RunPanel.svelte` so the user sees which repo is currently being fetched and how far through the Run they are, instead of the current bare "Running…" label.

On `runNow()`, before invoking `run_now`, subscribe to `run-progress` via `@tauri-apps/api/event`'s `listen()`, updating local `$state` (index/total/repo). While `running` is true and no event has arrived yet (covers the discovery phase, which never emits), keep today's plain "Running…" label. Once the first `run-progress` event arrives, render the repo/count text (e.g. "Fetching: repo-a (2/12)") and a determinate progress bar (index/total) in place of/alongside the button, styled with the existing token set (`src/lib/styles/tokens.css`). Unsubscribe the listener in the `finally` block alongside the existing `running = false` reset, so a completed or failed Run always leaves a clean slate for the next one.

No change to `SideDrawer`'s open/close behavior — the progress UI lives inside `RunPanel` exactly as the rest of the panel does today; closing the drawer just hides it, and reopening shows current progress again since the Run keeps going in the background.

## Acceptance criteria

- [ ] `RunPanel.svelte` subscribes to the `run-progress` event when a Run starts and unsubscribes when it ends (success or error).
- [ ] Before the first `run-progress` event arrives (discovery phase), the panel shows today's "Running…" label — no bar, no count.
- [ ] Once progress events arrive, the panel shows "Fetching: <repo> (<index>/<total>)" text and a determinate progress bar reflecting index/total, updating live as further events arrive.
- [ ] On Run completion or error, the panel returns to its idle state ("Get all data" button, error message if applicable) with no leftover progress text/bar and no leaked event listener.
- [ ] Closing and reopening the SideDrawer mid-Run does not affect the Run itself and shows current progress on reopen.
- [ ] Verified manually via `pnpm tauri dev` against a workspace with multiple repos (per this repo's no-JS-test-runner convention).
## Notes

RunPanel.svelte subscribes to run-progress on Run start, showing a determinate 'Fetching: <repo> (i/total)' progress bar once events arrive, falling back to the plain 'Running…' label during discovery. Listener is unsubscribed in the finally block and also on component unmount (defensive  cleanup).
