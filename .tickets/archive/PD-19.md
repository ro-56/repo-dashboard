## What to build

The amber structural notice strip, plus the two failure states that exist in `CONTEXT.md` and have no representation whatsoever in the reference design: **Fetch failure** and **Unresolvable membership**.

Under ADR-0005 neither may claim a hue of its own — hue encodes diff state and nothing else — so both express themselves as tags plus notice-strip prose.

## Acceptance criteria

- [ ] A 25px strip renders on `--notice-bg` (#fdf6e6) with a 3px inset `--notice-edge` (#a8791a) left edge, the `structural` eyebrow, and prose in `--notice-ink` (#5c4a14).
- [ ] The strip narrates, when present: repo absence, repo arrival, workspace departure, workspace arrival, fetch failures, and unresolvable memberships.
- [ ] Each category names up to three items then counts the rest — `core-api, auth-service, event-bus and 4 more repositories are absent from the comparison run`. The strip stays one line at any workspace size.
- [ ] The strip does not render at all when there is nothing structural to report.
- [ ] Selecting the same Snapshot for both sides shows the strip explaining that this is a single run's access list with no diff layered on it.
- [ ] A repo whose permissions call failed carries a `fetch failed` tag and renders no roster — visibly distinct from a repo fetched successfully with zero grants, which renders an empty roster without the tag.
- [ ] A group Principal whose membership could not be resolved carries a `members unresolved` tag on its group row and renders no Member rows beneath it — visibly distinct from a group confirmed to have zero members.
- [ ] Neither failure state introduces a new hue; both reuse the existing tag palette (ADR-0005).

## Out of Scope

- Retrying a failed fetch from the UI — collection is out of this epic entirely.
- Surfacing Discovery failure. A Discovery failure saves no Snapshot at all, so it can never appear in a Run pair; it belongs to the Run-now flow.

## Further Notes

The reference design has no design for a Fetch failure — the `fetch failed` tag is an invention of the design session, not the designer's. Worth review by whoever owns the visual design before this is considered final.
