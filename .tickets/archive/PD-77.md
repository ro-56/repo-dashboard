## Context

From the 2026-08-01 architecture review (candidate 3, \"Strong\"): `apply_one` in `src-tauri/src/apply.rs:81-128` matches `(GrantScope, EditTarget)` (4 combinations: Repo/Project × Direct/Group) × `EditAction` (Set/Remove) = 8 near-identical branches. Each branch just forwards `edit.repo`/`edit.repo_project`, an id, and an optional `Permission` to one of 8 structurally identical `BitbucketClient` write methods:
`set_repo_direct_permission`, `remove_repo_direct_permission`, `set_project_direct_permission`, `remove_project_direct_permission`, `set_repo_group_permission`, `remove_repo_group_permission`, `set_project_group_permission`, `remove_project_group_permission` (defined on the `BitbucketClient` trait, `src-tauri/src/client.rs`).

The interface (`apply_one`'s signature) is trivial; the real duplication is one layer down, in the trait surface itself — 8 methods that differ only in scope (repo/project) and target (direct/group) where two parameterized methods would do.

Deletion test: inlining `apply_one` into its caller wouldn't help — deleting it just moves the same 8-way match into `apply_pending_edits`. The fix is at the seam between `apply.rs` and `client.rs`, not inside `apply_one`.

## Design (settled via grilling session, 2026-08-02)

- **New type, owned by `client.rs`**: `PrincipalRef { Direct(String), Group(String) }`. `apply.rs`'s existing `EditTarget` converts into it at the call site inside `apply_one` — `client.rs` must not depend on `apply.rs`'s `EditTarget` (that would reverse/cycle today's dependency direction).
- **Collapsed trait surface** (replaces all 8 write methods):
  ```rust
  fn set_permission(&self, workspace: &str, scope: GrantScope, key: &str, principal: PrincipalRef, permission: Permission) -> impl Future<Output = Result<(), ClientError>> + Send;
  fn remove_permission(&self, workspace: &str, scope: GrantScope, key: &str, principal: PrincipalRef) -> impl Future<Output = Result<(), ClientError>> + Send;
  ```
  `key` is the repo slug when `scope == GrantScope::Repo`, the project key when `scope == GrantScope::Project` — mirrors how `PendingEditRequest` already carries both `repo` and `repo_project` and `apply_one` already picks the right one per scope. `GrantScope` is reused as-is from `model.rs`, no new type needed there.
- **`RealBitbucketClient` internals**: one private `permission_url(&self, workspace: &str, scope: GrantScope, key: &str, principal: &PrincipalRef) -> String` helper, branching once on `scope` for the base path (`repositories/{workspace}/{key}` vs. `workspaces/{workspace}/projects/{key}`) and once on `principal` for the segment (`users`/`groups`), composed into the full `.../permissions-config/{segment}/{id}` path. `set_permission`/`remove_permission` each become a one-line call to `write_with_retry` (PUT+body / DELETE) against that URL.
- **`apply_one`**: converts `edit.target: EditTarget` into a `PrincipalRef`, then makes a single call to `set_permission` or `remove_permission` depending on `edit.action` — no more 4-way `(scope, target)` match.
- **Test fake in `apply.rs`**: collapses from 8 parallel call-tracking vecs/result-maps to one `Vec<Call>` (`workspace`, `scope`, `key`, `principal`, `action: CallAction::Set(Permission) | Remove`) plus one canned-results map keyed by **`(GrantScope, id)`**, not id alone — avoids latent cross-scope collisions if a future test reuses the same principal id at both Repo and Project scope with different expected outcomes. Existing 16 tests' assertions get rewritten against this one vec/map; observable behavior (which request fires, with what args, what result comes back) stays the same.
- **`collect.rs` / `refresh.rs`**: grep-confirmed their `FakeBitbucketClient`-style test fakes implement all 8 write methods only as no-op stubs to satisfy the trait (never exercised — `apply.rs` owns the real write-path fake). These shrink mechanically to 2 no-op stubs (`set_permission`/`remove_permission`) each. No production logic in either file touches the write methods.
- **Explicitly out of scope**: the analogous 4-method duplication on the read side (`list_direct_permissions`/`list_project_direct_permissions`, `list_group_permissions`/`list_project_group_permissions`) is a real, separate change — `collect.rs` calls these directly in production logic (not just via test fakes), and their return types differ by principal kind (`RawUserPermission` vs. `RawGroupPermission`), so any collapse there is a different, larger design question. Leave all 4 untouched in this ticket.
- **No new ADR**: this is a pure internal trait-shape refactor with no behavior change and no new domain vocabulary — document `PrincipalRef` and the two new methods via doc comments in `client.rs` (matching the existing docstring style on the old 8 methods) instead.

## Acceptance criteria

- [ ] `client.rs` defines `PrincipalRef { Direct(String), Group(String) }` and `BitbucketClient` exposes `set_permission`/`remove_permission` (signatures above) instead of the 8 separate write methods.
- [ ] `RealBitbucketClient` implements both via a shared private `permission_url` helper; the 4 URL shapes (repo/project × direct/group) are still correct byte-for-byte versus today's hardcoded formats.
- [ ] `apply_one` converts `EditTarget` → `PrincipalRef` and becomes a single dispatch (one `set_permission`/`remove_permission` call per action), not an 8-way match.
- [ ] `apply.rs`'s test fake collapses to one `Call` vec + one `(GrantScope, id)`-keyed results map; all 16 existing tests pass with equivalent assertions (same requests fired for the same inputs).
- [ ] `collect.rs` and `refresh.rs` test fakes' write-method stubs shrink from 8 to 2 no-op methods each; both crates still compile and their existing test suites pass unchanged.
- [ ] The 4 read-side `list_*` methods are untouched.
- [ ] Grep confirms no other module referenced the removed 8 method names by the end of the change.
## Notes

Collapsed BitbucketClient's 8 write methods (set/remove x repo/project x direct/group) into set_permission/remove_permission parameterized by GrantScope and new PrincipalRef enum. RealBitbucketClient composes the 4 URL shapes via one permission_url helper (byte-identical to before). apply_one collapsed from an 8-way match to a single dispatch converting EditTarget->PrincipalRef. apply.rs's test fake collapsed from 8 call-vecs/result-maps to one Call vec + (GrantScope, id)-keyed results map; all 16 existing tests preserved plus 1 new test covering the same-id-different-scope collision case the ticket flagged. collect.rs/refresh.rs fakes shrunk from 8 no-op stubs to 2. Grep confirms no remaining references to the 8 removed method names. All 155 cargo tests pass.
