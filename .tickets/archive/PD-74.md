## What to build

Add a single "Export" action to the head bar that writes the current Comparison Snapshot's full roster to a CSV file, chosen via a native Save As dialog. Full spec and domain context: PD-72 (`taskr show PD-72`), ADR-0026 (`docs/adr/0026-roster-export-csv-only-carve-out.md`).

- New pure module (e.g. `src/lib/rosterExport.ts`):
  - `rosterToCsv(tree, runAt)` — flattens every `PrincipalEntry` into one CSV row: `repo_project, repo, username, display_name, access_type, scope, permission, run_at`. Diff-free and unfiltered always (ignores `diffStatus` and `ViewMode`).
  - `exportFilename(workspace, runAt)` — `roster_<workspace>_<run-seq-or-timestamp>.csv`, reusing `headBar.ts`'s existing run-labeling convention where practical.
  - RFC 4180-style escaping for fields containing a comma, quote, or newline. No external CSV library.
- Data source: reuse the existing `get_roster_tree` command, called as `get_roster_tree(comparisonId, comparisonId)` to get an undiffed tree for the Comparison Snapshot alone, regardless of the dashboard's current Run pair selection.
- UI: an "Export" action in `HeadBar.svelte`, alongside the existing Run-pair selectors and Run now action, using the plugin wiring from PD-73 to open the Save As dialog and write the generated CSV.
- **Styling**: the Export action's markup and styling must match the finalized visual design in `.references/new-design/` — use the existing mockups as the source of truth for how a head-bar action should look (spacing, color tokens, hover/focus states), not a one-off style. It should look like it belongs next to the existing Run now/selector controls, not bolted on.

## Acceptance criteria

- [ ] `rosterToCsv`, `exportFilename`, and the escaping helper are covered by colocated vitest tests (`rosterExport.test.ts`), following the fixture-in/string-out pattern of `rosterRow.test.ts`/`repoCard.test.ts`/`headBar.test.ts`.
- [ ] Test cases include: Direct/Group/Member access-type rendering, `CreateRepo` displayed as `create-repo` (never collapsed to `admin`), a Principal with both a Repo-scope and Project-scope row on the same repo (both rows present, not merged), comma/quote/newline escaping, and the diff-free guarantee (non-`None` `diffStatus` input still produces no diff markers in output).
- [ ] Clicking Export in the dashboard opens a native Save As dialog defaulting to the `exportFilename` output, and writes a CSV whose content matches `rosterToCsv`'s output for the current Comparison Snapshot — verified manually via `pnpm tauri dev`.
- [ ] Export always exports the whole workspace, always the Comparison Snapshot (never the Baseline), regardless of the dashboard's current view-mode filter or Run pair selection.
- [ ] The Export action's visual styling is verified by eye against `.references/new-design/` (token sheet + mockups) — same spacing/color-token/hover-focus conventions as the existing head-bar controls.
- [ ] `pnpm test`, `pnpm check` pass.
