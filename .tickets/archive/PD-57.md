## What to build

Port `perm-diff.css`'s `:root[data-theme="dark"]` block into `tokens.css`, mapped onto the same custom-property names `tokens.css` already uses for light (the PD-36 name mapping, not `perm-diff.css`'s literal names). Add a `theme.ts` module exposing the current theme, a setter, and an init read (`localStorage` first, else a one-time `prefers-color-scheme` check). Add a fourth `appearance` panel to `SideDrawer` with a Light/Dark segmented toggle. Supersedes PD-39 — PD-39 should be closed as a duplicate once this lands.

## Acceptance criteria

- [ ] `:root[data-theme="dark"]` block exists in `tokens.css` with `perm-diff.css`'s dark values, mapped onto the same names `tokens.css` already uses for light
- [ ] `--shadow-drawer` (added in the drift-fix ticket) gains its dark-theme value (`-8px 0 20px rgba(0,0,0,.45)`)
- [ ] `theme.ts` exposes current theme (`"light" | "dark"`), a setter, and an init function reading `localStorage`, falling back to a one-time read of `prefers-color-scheme` when no stored value exists (no live `matchMedia` listener — an explicit stored choice is never overridden by a later OS-level change)
- [ ] The setter persists to `localStorage` and applies the theme via `data-theme` on the root `<html>` element, instantly, with no reload and no per-component JS branching
- [ ] `SideDrawer` gains an `appearance` panel (same `.panel`/`.panel + .panel` structure as credentials/run/snapshots) with a Light/Dark segmented pill toggle, styled like `FilterBar`'s existing segmented control (`--track`/`--track-active`/`--shadow-segment`)
- [ ] Toggling switches the whole dashboard (head bar, filter bar, roster rows, repo cards, tags, chips, drawer) instantly, with no reload
- [ ] Theme choice persists across an app relaunch
- [ ] First launch with no stored preference defaults to the OS's `prefers-color-scheme`
- [ ] Colocated `theme.test.ts` covers `localStorage` read/write and the `prefers-color-scheme` fallback, including that an explicit stored choice is never overridden by a later OS-preference change
- [ ] `pnpm check` passes
- [ ] Verified via `pnpm tauri dev`: toggle, relaunch persistence, first-launch OS-default behavior, and a full pass over every component in dark mode to confirm no color looks wrong
