## What to build

The 31px filter bar's first inhabitants — the All access / Changes only segmented tab, the row-count note, and the bulk expand controls — plus the two empty states that stop the console looking broken when there is nothing to draw.

Supersedes PD-14, which specified the same behaviour against the pre-rebuild layout.

## Acceptance criteria

- [ ] A segmented control offers `All access` and `Changes only`, active segment on `--ink` with white text, inactive on `--surface`, sharing one 2px-radius bordered box.
- [ ] `Changes only` hides roster rows with no diff marker and hides repo cards whose change count is zero.
- [ ] The `N live · N changed · N rows` note reflects the current view and is the **only** readout that does — the summary bar from PD-18 stays workspace-wide regardless (design-session decision).
- [ ] `Expand all` opens every visible card; `Collapse all` closes every card, giving the all-collapsed overview PRD §5.4 requires as state `1b`. The control's label reflects which action it will perform.
- [ ] `Reset` returns the view to All access with the PD-16 default expand rule reapplied.
- [ ] With `Changes only` active and a Run pair that has zero changes across the whole workspace, the no-changes state (`1h`) renders — a bordered `--surface` card with title, body and an action — not a blank canvas.
- [ ] With a view that leaves nothing renderable, the no-matches state (`1i`) renders with its own copy and a reset action.
- [ ] Switching back to `All access` restores the previous expansion state rather than resetting it.
- [ ] Escalation rows keep their amber wash in every view — the tab filters rows, it does not alter row styling (ADR-0007).

## Out of Scope

- Project and repo dropdowns, level chips, state chips, username search, density switch — the follow-up filters epic. Build the bar so they can be added without relayout.
- Persisting view state across app restarts.
