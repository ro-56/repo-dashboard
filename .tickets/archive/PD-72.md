## Problem Statement

There's no way to get the roster data out of repo-dashboard as a plain file. Today the dashboard is the only place permission data can be seen — which is fine for day-to-day auditing, but two needs fall outside it: handing a snapshot of current access to a reviewer (e.g. attached to an email) who doesn't have the app installed, and keeping an offline archival copy of a Run's roster independent of the app's own SQLite storage.

## Solution

Add a single "Export" action, reachable from the head bar, that writes the currently-selected Comparison Snapshot's full roster to a CSV file on disk via a native OS "Save As" dialog. The dashboard remains the single source of truth for ongoing audits — Export produces a one-off, point-in-time data file, not a parallel reporting workflow. This carves out a narrow exception to the PRD's existing "no Excel/CSV export" non-goal (see ADR-0026, `docs/adr/0026-roster-export-csv-only-carve-out.md`).

## User Stories

1. As an admin auditing repository access, I want to export the current roster to a file, so that I can send it to a reviewer who doesn't have the app installed.
2. As an admin, I want to keep an offline archival copy of a Run's roster, so that I have a record independent of the app's own database.
3. As an admin, I want the exported file to be a plain CSV, so that I can open it in any spreadsheet tool without needing the app.
4. As an admin, I want Export to always produce the full roster regardless of any active view filter, so that I never accidentally send a reviewer an incomplete picture because I had "Changes only" selected on screen.
5. As an admin, I want Export to always be diff-free (a flat single-Snapshot roster), so that the exported file doesn't need a legend to explain Grant/Revoke/Escalation markers — it just states current permissions.
6. As an admin comparing two Runs in the dashboard's diff view, I want Export to use the newer (Comparison) Run rather than the older (Baseline) one, so that the exported file matches "current state," not "state as of the older Run."
7. As an admin, I want to pick exactly where the exported file is saved via a native Save As dialog, so that I can put it directly in the location I'm about to attach from or archive to, rather than hunting for it in an app-managed folder afterward.
8. As an admin, I want the exported filename to default to something that identifies the workspace and Run, so that I don't have to rename a generic file before sending it or filing it away.
9. As an admin, I want Export to cover the whole workspace in one file, so that I don't have to stitch together per-repo exports myself.
10. As an admin, I do not want the app to send email on my behalf, so that I keep full control over who receives the exported file and when.
11. As an admin, I want each CSV row to state a permission's grant scope (repo-level vs. project-level cascade), so that the file is a faithful, lossless copy of what the dashboard itself tracks — not a lossy summary.
12. As an admin, I want each CSV row to state the access type (direct, group, or member-of-group), so that I can tell how someone holds a permission without cross-referencing the app.
13. As an admin, I want the CSV to include the Run's timestamp on every row, so that the file is self-describing even if it's separated from its filename later.

## Implementation Decisions

- **New module**: a pure TypeScript module (e.g. `src/lib/rosterExport.ts`), following the codebase's existing pattern of pure presentation/data-shaping logic colocated with a component (`filterBar.ts`, `repoCard.ts`, `rosterRow.ts`), not new Rust code — no new Tauri command is required.
- **Data source**: the existing `get_roster_tree` Tauri command is reused, called with the Comparison Snapshot's id for both arguments (`get_roster_tree(comparisonId, comparisonId)`) to obtain an undiffed, full `RosterTree` for that Snapshot alone — regardless of whatever Run pair is currently selected in the dashboard's diff view.
- **CSV content function**: `rosterToCsv(tree: RosterTree, runAt: string): string` flattens every `PrincipalEntry` across every `ProjectNode`/`RepoNode` into one CSV row each, ignoring `diffStatus` entirely (every row is a plain current-state row) and ignoring the dashboard's `ViewMode` (all vs. changes-only) — Export always covers every row regardless of what's currently filtered on screen.
- **CSV columns**: `repo_project, repo, username, display_name, access_type, scope, permission, run_at`. `username`/`display_name` are sourced from `Principal.id`/`Principal.label` respectively (Principal is the current domain term; the PRD-era model used `username`/`display_name` as flat fields, which this maps onto). `access_type` is `direct`, `group`, or `member:<group_id>` (mirroring the existing `AccessType` enum's wire shape). `scope` is `repo` or `project` (`GrantScope`). `permission` is the display-level permission string (`read`/`write`/`create-repo`/`admin` — `CreateRepo` is shown as its own value here, per ADR-0024, never collapsed onto `admin` for a value being *displayed*).
- **CSV escaping**: standard RFC 4180-style quoting for any field containing a comma, quote, or newline (repo/display names can contain these). No external CSV library — this is a small, fully-specified format not worth a dependency.
- **Filename**: `roster_<workspace>_<run-seq-or-timestamp>.csv`, generated by a small pure function (e.g. `exportFilename(workspace: string, runAt: string): string`), reusing the existing run-labeling convention from `headBar.ts` (`snapshotSeqs`) where practical so the filename's Run identifier matches what the head bar itself calls that Run.
- **Trigger point**: a single "Export" action added to `HeadBar.svelte`/`headBar.ts`, alongside the existing Run-pair selectors and Run now action. Whole-workspace only — no per-repo export action.
- **Save mechanism**: `@tauri-apps/plugin-dialog`'s save dialog (native OS "Save As"), followed by `@tauri-apps/plugin-fs`'s file-write API to write the generated CSV string to the chosen path. Neither plugin is currently a dependency — both need adding to `Cargo.toml`, `package.json`, and the Tauri capabilities/permissions config (`src-tauri/capabilities/`) that gates plugin access.
- **No email integration**: Export's responsibility ends at writing the file to the path the user picked. No SMTP, no mail client invocation, no recipient field anywhere in this feature.
- **No HTML export**: considered and explicitly dropped for this iteration — see ADR-0026 for why (DOM-serialization and a hand-maintained parallel markup generator were both judged too much machinery for the stated need). CSV alone satisfies both the "email a reviewer" and "offline archive" use cases from the user stories.

## Testing Decisions

- Good tests here exercise `rosterToCsv`, `exportFilename`, and any escaping helper purely on their inputs/outputs (a `RosterTree` fixture in, a CSV string out) — no Svelte rendering, no Tauri plugin calls, matching the project's existing pure-TS-module convention (ADR-0017: Svelte component rendering and end-to-end/Tauri-integration testing are deferred; only pure logic modules get colocated vitest tests).
- Prior art to follow directly: `src/lib/rosterRow.test.ts`, `src/lib/repoCard.test.ts`, `src/lib/headBar.test.ts` — same shape of fixture-in/value-out unit tests, colocated next to the module they cover.
- Cases worth covering in `rosterExport.test.ts`: a Direct grant row, a Group grant row, a Member grant row (correct `access_type` rendering for each); a `CreateRepo` permission row (displayed as `create-repo`, not collapsed to `admin`); a Repo-scope and a Project-scope row for the same Principal on the same repo (both rows present, not merged — mirrors ADR-0012's existing invariant); a value containing a comma/quote/newline (escaping is correct); the diff-free guarantee (feeding in a `RosterTree` with non-`None` `diffStatus` values still produces a CSV with no diff markers/columns); and `exportFilename` producing a stable, expected string for a given workspace/timestamp input.
- The Tauri plugin wiring (dialog + fs) itself is UI/integration plumbing, not unit-tested — verified manually via `pnpm tauri dev` (open the Save As dialog, confirm a file lands at the chosen path with the expected default name and content), consistent with how other Svelte/CSS changes in this codebase are verified per ADR-0017.

## Out of Scope

- HTML export, or any export format beyond CSV (see ADR-0026's rejected-options section).
- Actually sending email from within the app (SMTP, compose window, recipient management).
- Per-repo export actions — export is whole-workspace only.
- Exporting the Baseline side of a Run pair, or any diff-aware export (Grant/Revoke/Escalation markers, filter/view-mode state) — CSV is always a flat, diff-free, unfiltered Comparison-Snapshot roster.
- An app-managed export history/folder, or a "reveal in file manager" action — the user picks the destination fresh each time via the native Save As dialog.
- Reopening the broader PRD non-goal around Excel/CSV as a *recurring* reporting path — this feature is explicitly a one-off, on-demand artifact, not a new standing output format the dashboard needs to keep in sync going forward.

## Further Notes

- This feature required amending the PRD (`.references/PRD.md`) and `CLAUDE.md` non-goals sections, and adding `docs/adr/0026-roster-export-csv-only-carve-out.md` and a `CONTEXT.md` "Export" glossary entry, to carve out this exception from the prior absolute "no Excel/CSV export" wording — done as part of this ticket's grilling session, already committed to those docs.
- If a formatted/shareable HTML export is wanted later, it should get its own ADR rather than being bolted onto this one, since ADR-0026 records specific reasons (DOM-serialization complications, interactive-chrome stripping) that would need to be addressed rather than assumed away.
