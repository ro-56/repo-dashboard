## What to build

An automated test that asserts every non-English locale catalog (pt-BR) has exactly the same set of keys as the English source-of-truth catalog — no missing keys, no stale/orphaned keys left over from removed strings. This is the only automated backstop against `svelte-i18n`'s silent-fallback-to-English behavior masking real translation gaps as new features land (per PD-79's testing decisions).

Only meaningful once the real content extraction (roster tree + chrome/drawer) has landed, since it validates the full catalog rather than an empty/partial one.

## Acceptance criteria

- [ ] Test fails if a key exists in the English catalog but not in pt-BR, or vice versa
- [ ] Test currently passes against the fully-migrated catalogs
- [ ] Colocated with the catalog files per this repo's `*.test.ts` convention (ADR-0017)
