## What to build

The core **Excluded principal** filtering logic and the row-level action to add an exclusion, per PD-90.

- A new `isExcluded(entry, excludedIds)` predicate, colocated in `rosterRow.ts` next to `matchesSearchQuery`.
- Folded into `isEntryVisible` in `filterBar.ts` as a third AND-ed condition alongside view mode and Principal search — no new visibility mechanism needed, `visibleRepos`/`viewCounts` reuse the existing repo-disappears-at-zero-rows / count-recompute machinery.
- Cascade rule (ADR-0032, `docs/adr/0032-excluded-principal-group-cascade-scoped-to-member-rows.md`): an entry is hidden if its own `principal.id` is excluded, OR it's a `Member` entry whose `accessType.group_id` is excluded. An unrelated `Direct`/`Group` entry belonging to the same person is never swept in.
- Exclusion set lives as session-scoped UI state (same lifecycle/home as Principal search's query state) — not persisted, not staged against any Snapshot, survives Baseline/Comparison navigation.
- `RosterRow.svelte` gains a quiet "Hide" text link, revealed on hover, sitting next to (not inside) the existing `⋯` menu trigger. Renders unconditionally — independent of `editTargetForEntry`/`editingEnabled` — so it appears on `Member` rows and under historical (non-latest) Comparisons too, since hiding is not an edit (ADR-0021/ADR-0022's editing-scope restrictions don't apply).
- The existing `FilterBar` Reset control also clears the exclusion set, in addition to what it already resets.
- Not respected by CSV Export (ADR-0026) — no change needed there, just don't wire it in.

## Acceptance criteria

- [ ] `isExcluded` predicate implemented and unit-tested in `rosterRow.test.ts`.
- [ ] `isEntryVisible`/`visibleRepos`/`viewCounts` extended and tested in `filterBar.test.ts`: blank exclusion set is a no-op, AND-composes with an active search and with Changes-only mode, a repo with only excluded rows drops out of `visibleRepos`, counts recompute over exactly what's left.
- [ ] Cascade rule tested: excluding a Group hides its own row and every derived `Member` row, but not an unrelated `Direct` grant on the same person (User Story 5).
- [ ] Excluding a user (not a group) hides every entry carrying that user's own `principal.id` across all access types.
- [ ] "Hide" link renders on every row, including `Member` rows and rows under a historical Comparison, regardless of whether the `⋯` menu itself is present for that row.
- [ ] Clicking "Hide" adds the entry's `principal.id` to session state and the matching rows disappear from the tree immediately, tree-wide (all repos/projects).
- [ ] Reset clears the exclusion set along with its existing resets (search text, expand/collapse overrides).
- [ ] Manually verified via `pnpm tauri dev` (Svelte rendering, no Playwright/component tests per ADR-0017).
