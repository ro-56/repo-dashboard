## What to build

A repo that is visible in the Roster tree only because it satisfies the active Principal search (not because it carries any Grant/Revoke/Level-change) should open automatically by default, using the same mechanism that already auto-opens a repo carrying changes.

- A repo matched by an active search defaults to open, even with zero diff activity.
- A user's manual collapse of a search-matched repo still overrides the auto-expand default, exactly as manual toggling already overrides the existing changes-based default-open rule — the user's own click always wins.
- No change to the default-open rule's behavior when no search is active — this only adds a new condition, it doesn't alter existing changes-based or empty-tree behavior.

Depends on the base search/narrowing behavior (blocked by the ticket that adds the search predicate and repo-level filtering).

## Acceptance criteria

- [ ] The default-open computation includes an added condition: a repo satisfying the active search defaults to open, independent of whether it has any diff activity.
- [ ] A repo matching the active search but manually toggled closed by the user stays closed.
- [ ] Existing changes-based default-open behavior is unchanged when no search is active (regression coverage).
- [ ] Colocated unit tests cover: search-match-with-no-changes defaults open; search-match-with-manual-toggle stays closed; no-match/no-changes follows the pre-existing default rule unchanged.
- [ ] Manually verified via `pnpm tauri dev`: typing a search auto-opens previously-collapsed, unchanged repos that match, and a manually re-collapsed matched repo stays collapsed.
