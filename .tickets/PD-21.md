## What to build

Window sizing and the reflow rules that let the console survive from its design width of ~1400 down to roughly 900, in the shed order fixed by ADR-0009.

Last in the epic because you cannot shed chrome that has not been built.

## Acceptance criteria

- [ ] The Tauri window defaults to 1440×900 with a `minWidth` of ~900, replacing the scaffold's 800×600.
- [ ] Between ~1400 and ~900 the layout gives way in this order and no other: repo card grants text → the 58px distribution bar → project meta → summary bar wraps to two rows → the transition column compresses from `read → write` to `→ write`.
- [ ] The roster row keeps all seven columns at every supported width. The grant-source column in particular never drops — under ADR-0006 it is row identity, and without it two Member grants for the same user are indistinguishable.
- [ ] At the 900px floor the console is still usable: no horizontal scrollbar on the roster, no overlapping text, no clipped tags.
- [ ] The head bar's Baseline and Comparison selectors remain fully readable at the floor; the span note may truncate before they do.
- [ ] Vertical overflow scrolls the canvas only — the head bar, summary bar, filter bar, notice strip and column-label strip stay fixed.

## Out of Scope

- Any width below ~900. PRD §3 describes a single admin on a desktop; a mobile or tablet layout is not a goal.
- The compact/regular density switch — deferred to the filters epic. Density and width are independent concerns.

## Further Notes

The reference states a fixed density budget "at 1440×900" and does not reflow at all; supporting 900 is a deliberate extension, recorded in ADR-0009 along with the reason the shed order runs chrome-first.
