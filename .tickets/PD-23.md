## What to build

Per ADR-0010 (`docs/adr/0010-dashboard-is-entrypoint-credentials-in-drawer.md`): remove the separate `/` landing route entirely. `/dashboard` becomes the app's sole entrypoint.

Add a control in the HeadBar that opens a side drawer (persistent slide-out panel, not a modal — chosen because the drawer's contents are expected to grow over time). The drawer's first sub-panel is credentials management:

- Idle state: "connected as `username` on `workspace`" (reads `get_credentials` from PD-22), with an option to change credentials.
- Edit state: the existing username / app password / workspace form (ported from the old `/` page), wired to `set_credentials`.

## Acceptance criteria

- [ ] `/` route removed; navigating to the app opens `/dashboard` directly
- [ ] HeadBar has a visible control that opens/closes the side drawer
- [ ] Drawer's credentials panel shows "connected as `username` on `workspace`" when credentials are already set (on fresh launch, after a restart)
- [ ] Drawer's credentials panel shows an edit form when no credentials are set yet, or when the user chooses to change them
- [ ] Submitting the edit form calls `set_credentials` and returns to the idle "connected as" state
- [ ] Drawer styling uses `tokens.css` design tokens (no hardcoded hex values)
