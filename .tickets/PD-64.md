## What to build

Bitbucket's Project-level API returns `create-repo` as a real permission value. The permission parser currently panics on it, crashing the entire Run. Fix the crash by adding `create-repo` as a real, ordered `Permission` value (`Read < Write < CreateRepo < Admin`, matching Bitbucket's true hierarchy), and make it compute as admin-equivalent everywhere the diff engine and roster summary counts do math — per ADR-0024 and the PD-63 spec.

Any permission string that is genuinely unrecognized (none of `read`/`write`/`create-repo`/`admin`) must be skipped at record granularity with a logged warning, not panicked on — mirroring how a fetch failure already degrades gracefully instead of failing the whole Run.

This ticket is backend-only (the Rust crate). It must leave the crate compiling and all behavior correct on its own — the frontend doesn't need to know about `create-repo` yet for this ticket to be complete and safe to ship (see PD-63 spec for why that's a safe intermediate state).

## Acceptance criteria

- [ ] Permission parsing recognizes `create-repo` (case-insensitive) and produces a real, distinct value — never a panic.
- [ ] The permission type's ordering is `Read < Write < CreateRepo < Admin`, so any direct comparison is trustworthy without special-casing.
- [ ] A dedicated collapsing helper (admin-equivalent) exists and is the only thing used for diff classification and roster counting — never for anything that displays a permission value.
- [ ] All four normalize functions (repo/project × user/group) skip a record with a genuinely unrecognized permission string, log a warning with the raw string and repo/project/principal context, and leave the containing repo/project's fetch status untouched (not `FetchFailed`) — the rest of the Run completes normally.
- [ ] `create-repo` round-trips correctly through Snapshot storage (persist and reload).
- [ ] Diff engine: a transition from `Write` to `create-repo` classifies as an Escalation.
- [ ] Diff engine: a transition between `create-repo` and `Admin` (either direction) produces no diff event at all — same effective access level.
- [ ] Roster summary counts (both the workspace-wide and per-repo figures): a `create-repo` grant counts into the existing admin bucket, not a new bucket.
- [ ] `cargo test` covers all of the above, including a new colocated test module for the permission type itself (parse + collapse behavior).
- [ ] A workspace containing a `create-repo` grant at Project level completes a full Run without crashing.

## Out of scope

- Frontend labeling/styling of `create-repo` (PD-65).
- A `none` permission value — confirmed not real for this API.
- Any change to the permission-editing feature's scope (ADR-0021).
