# `create-repo` is a real, distinct Permission level, but computes as Admin everywhere

`Permission::parse` panicked on Bitbucket's Project-level `create-repo` value (PD-58), crashing the whole Run since none of the four normalize call sites had per-record recovery. Verified against Atlassian's docs that the real Project permission hierarchy is `Admin ⊃ Create ⊃ Write ⊃ Read` (each level includes everything below it) — `create-repo` is a genuine fourth rung, not a Data Center-only artifact and not orthogonal to the read/write/admin ladder. (An initially-suspected fifth value, `none`, turned out not to be documented for this endpoint — ADR-0021's mention of it was an unverified assumption; there is no `Permission::None`.)

Two pure options were rejected: aliasing `"create-repo"` straight to `Permission::Admin` at parse time (simplest, but the tool loses the ability to ever show a user *which* of the two they actually hold — contradicts this tool's whole premise of permission visibility); and giving `create-repo` full first-class treatment with its own counts/segments everywhere (correct, but drags in an ADR-0008 distribution-bar redesign and new UI real estate for a bug-fix ticket).

Landed in between: `Permission` gets a real `CreateRepo` variant, in true hierarchy position (`Read < Write < CreateRepo < Admin`, so direct `Ord` comparisons stay honest), and it round-trips through storage and displays as `"create-repo"` on a roster row — so the user always sees which of the two they hold. But everywhere the code *computes* rather than *displays* — the diff engine's equality/escalation-demotion classification (`diff.rs`) and the roster's summary counts (`LevelCounts`/`RepoNode` in `roster.rs`, `RANK`/`LEVEL_CLASS` in `rosterRow.ts`) — `CreateRepo` collapses onto `Admin` via a dedicated `admin_light`-style helper, not `Permission`'s own `Ord`/`Eq`. A `CreateRepo ↔ Admin` transition between two Runs is therefore invisible as a diff event (same effective access), while a `Write → CreateRepo` transition still surfaces as an Escalation, tagged the same as an escalation to Admin.

## Consequences

- Any future code path that needs "the level" for display should use `Permission` directly; any path doing arithmetic, counting, or diff classification must go through the collapsing helper, not raw `Permission` comparison — the two are deliberately not interchangeable.
- The distribution bar (ADR-0008) still renders 3 segments; `CreateRepo` records count into the `admin` segment. Giving `create-repo` its own visual segment is a follow-up ticket, not part of this fix.
