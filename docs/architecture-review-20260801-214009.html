Problem: the same domain types exist twice — once as Rust enums with serde tagging, once as hand-written TS unions that must track them. pendingEdits.ts even types ApplyResult.outcome as {Ok: null} | {Err: ApplyError} to match Rust's Result serialization verbatim. A renamed/added Permission variant in Rust doesn't force the TS side to follow — the failure mode is silent runtime drift, not a compile error.

Solution: worth exploring a codegen seam (e.g. ts-rs or `specta`) that derives the TS types from the Rust source of truth, so the two sides can't drift silently.

  • Locality: one edit (in Rust) updates both sides
  • Removes a class of bug the type system currently can't catch
  • Scope: touches build tooling, not just app code — worth a dedicated grilling pass before committing
