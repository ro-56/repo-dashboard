Repo Dashboard

Uma ferramenta de desktop para auditar quem tem acesso aos repositórios Bitbucket Cloud da sua equipe — e detectar quando esse acesso muda.

O que isso faz

Qualquer pessoa com direitos de administrador no seu workspace do Bitbucket pode alterar quem tem acesso a um repositório a qualquer momento, e o Bitbucket não guarda um histórico dessas alterações. O Repo Dashboard preenche essa lacuna:

  • Ele examina cada repositório do seu workspace do Bitbucket e registra exatamente quem tem acesso a quê.
  • Cada varredura é salva permanentemente como um snapshot datado — uma fotografia de "como estava o acesso neste momento" que nunca muda depois.
  • Escolha dois snapshots quaisquer e o dashboard mostra o que mudou entre eles: quem ganhou acesso, quem perdeu, e o nível de acesso de quem subiu ou desceu — com qualquer coisa que pareça um escalonamento arriscado (por exemplo, leitura → admin) destacada especificamente.
  • Na mesma tela, você pode corrigir problemas diretamente — reduzir ou remover o acesso de alguém — sem sair do aplicativo.
  • Você pode exportar um snapshot para um arquivo CSV, caso precise compartilhá-lo com alguém.

Ele roda inteiramente no seu próprio computador. O único tráfego de rede que produz é a comunicação com o próprio Bitbucket — nada é enviado a mais nenhum lugar, e todos os dados dos seus snapshots ficam na sua máquina.

Primeiros passos

Abrindo o aplicativo

O Repo Dashboard é um aplicativo de desktop comum — alguém já o compilou para você, então não há nada para instalar ou compilar. Basta dar um duplo clique nele (ou executar o arquivo) como qualquer outro programa do seu computador.

Criando um API token do Bitbucket

Para que o Repo Dashboard converse com o Bitbucket em seu nome, você precisará de um API token do Bitbucket. Pense nisso como uma senha especial que só serve para essa finalidade, e que só faz o que você permitir — você a cria uma vez, cola no aplicativo, e nunca mais precisa digitar sua senha real do Bitbucket em lugar nenhum.

Ao criar o token no Bitbucket, será pedido que você marque uma lista de "escopos" ("scopes") — caixas de seleção que controlam o que o token pode fazer. Marque as seguintes:

EscopoNecessário para
read:project:bitbucketVer o acesso em Projetos
read:repository:bitbucketVer o acesso em repositórios
admin:project:bitbucketAlterar ou remover acesso em um Projeto
admin:repository:bitbucketAlterar ou remover acesso em um repositório
write:permission:bitbucketAlterar o nível de acesso de alguém
delete:permission:bitbucketRemover o acesso de alguém
Só vai consultar? Se você só quer ver quem tem acesso — o roster e as comparações entre duas datas — os dois escopos read: acima já bastam. Marque os escopos admin:, write:permission: e delete:permission: apenas se também quiser alterar ou remover o acesso de pessoas de dentro do aplicativo (veja Alterando ou removendo acesso).

Primeiro acesso: conectando ao Bitbucket

Na primeira vez que você abrir o aplicativo, ele ainda não terá nenhum dado. Abra o painel de configurações (o ícone de engrenagem, no canto superior direito) e preencha o painel de credenciais:

  1. Usuário — seu nome de usuário no Bitbucket Cloud.
  2. Senha de aplicativo — o API token que você criou acima.
  3. Workspace — o nome do workspace do Bitbucket que você quer auditar (o Repo Dashboard trabalha com um workspace por vez).

Clique em Salvar credenciais. Isso é armazenado com segurança pelo próprio gerenciador de senhas do seu computador (Keychain no Mac, Gerenciador de Credenciais no Windows, ou o equivalente no Linux) — nunca como um arquivo de texto simples, e o aplicativo nunca mostrará a senha de volta depois de salva.

Se você pulou os escopos de admin/write/delete acima, ver o roster continuará funcionando normalmente — você só terá problemas se mais tarde tentar alterar ou remover o acesso de alguém, o que será rejeitado. Se isso acontecer, volte ao Bitbucket, adicione os escopos que faltam ao seu token, e salve o token atualizado no painel de credenciais.

Depois de conectado, você pode reabrir o painel a qualquer momento em Alterar credenciais para atualizar o usuário, o token ou o workspace.

Sua primeira execução

Ainda no painel de configurações, clique em Obter todos os dados para buscar seu primeiro snapshot. Veja Tirando um snapshot abaixo para entender o que acontece nessa etapa.

Conceitos principais

Alguns termos aparecem repetidamente no dashboard. Entendê-los desde já facilita entender o resto da interface.

Principal
Quem quer que tenha acesso — uma pessoa ou um grupo. As pessoas são identificadas pela conta que estão por trás, não pelo nome de exibição, então se alguém mudar de nome isso nunca é confundido com uma pessoa saindo e outra nova chegando.
Acesso direto / de grupo / por associação
Direto — acesso concedido a uma pessoa nomeada.
Grupo — acesso concedido a um grupo como um todo.
Membro — acesso que uma pessoa tem apenas por pertencer a um grupo que recebeu acesso. Aparece em sua própria linha mesmo para alguém que também tenha acesso direto no mesmo repositório, já que são duas coisas separadas e podem ser removidas independentemente.
Nível de repositório vs. nível de Projeto
O acesso pode ser concedido em um repositório específico, ou no Projeto ao qual ele pertence — o acesso em nível de Projeto cobre automaticamente todos os repositórios daquele Projeto. O dashboard marca as linhas em nível de Projeto com uma seta "↳".
Execução
Uma verificação completa de todo o workspace: cada repositório e Projeto é examinado novamente do zero. Produz um novo snapshot.
Atualização
Uma nova verificação rápida e restrita, apenas dos repositórios/Projetos que você acabou de editar — bem mais rápida que uma execução completa, mas não percebe repositórios totalmente novos (veja Atualizando).
Snapshot
O resultado salvo de uma Execução ou Atualização: uma fotografia completa do acesso naquele momento, congelada no tempo. Snapshots podem ser excluídos, mas nunca editados.
Base / Comparação
Os dois snapshots que você está comparando. A Base é "como era antes", a Comparação é "como está agora". Toda alteração exibida é lida como um movimento da Base para a Comparação.
Concessão / Revogação / Escalonamento / Rebaixamento
+ Concessão — acesso que é novo na Comparação; não existia na Base.
− Revogação — acesso que desapareceu na Comparação; existia na Base.
~ Mudança de nível — o mesmo acesso existe nas duas, só que em um nível diferente: um Escalonamento se subiu, um Rebaixamento se desceu.

Tirando um snapshot ("Obter todos os dados")

No painel de configurações, clique em Obter todos os dados. Isso dispara uma varredura completa do workspace:

descobre cada repositório e Projeto do workspace │ ▼ para cada um: busca concessões diretas, concessões de grupo, e (quando possível) concessões derivadas de associação a grupo │ ▼ salva tudo como um novo snapshot, com data e hora

Enquanto roda, uma barra de progresso mostra qual repositório está sendo buscado no momento e quantos faltam. Ao terminar, o dashboard passa automaticamente a comparar o novo snapshot com o anterior.

Se a primeira etapa (descobrir os repositórios) falhar — por exemplo, se sua credencial for rejeitada de cara — toda a Execução é interrompida e nada é salvo; o erro aparece diretamente na tela. Se a descoberta funcionar mas a busca de um repositório ou Projeto específico falhar no meio do caminho, apenas esse repositório/Projeto é marcado como falha na busca no snapshot resultante, e o resto da Execução continua normalmente — isso não é tratado como uma Execução malsucedida.

Uma Execução sempre leva você para a comparação mais recente vs. anterior, mesmo que você tivesse escolhido manualmente um par mais antigo para visualizar.

Lendo o dashboard

A visão principal é organizada como Projeto → repositório → principal. Cada Projeto tem um cabeçalho com a contagem de repositórios/concessões; cada repositório é um cartão que pode ser expandido ou recolhido.

Cartões de repositório

O cabeçalho de cada cartão mostra, da esquerda para a direita: uma seta de expandir/recolher, o caminho Projeto/repositório, uma pequena barra de distribuição admin/escrita/leitura, uma contagem de concessões ("7 concessões · 2 admin"), e badges resumindo o que mudou naquele repositório (+2 −1 ~1, ou sem alteração). Repositórios com pelo menos uma alteração se abrem automaticamente ao carregar a página; se nada mudou em toda a comparação, todos os cartões se abrem em vez disso (assim você nunca vê uma tela toda recolhida e aparentemente vazia).

Um cartão de repositório também pode exibir uma etiqueta ao lado do nome:

EtiquetaSignificado
ausente na execução NEste repositório existia na Base, mas desapareceu na Comparação (foi renomeado, arquivado, ou não é mais visível para a credencial usada).
novo na execução NEste repositório não existia na Base, mas aparece na Comparação.
falha na buscaO repositório foi descoberto, mas suas próprias permissões não puderam ser buscadas nesta Execução — suas concessões são simplesmente desconhecidas, não "zero".
falha na busca do projetoA chamada de permissões do Projeto dono falhou (independentemente de a busca do próprio repositório ter funcionado ou não).

Linhas dentro de um cartão

Cada linha representa a concessão de um principal naquele repositório. Colunas, da esquerda para a direita:

ColunaMostra
±Um símbolo para o estado da diferença da linha: + concessão, − revogação, ↑ escalonamento, ~ outra mudança de nível, · sem alteração.
nívUm pequeno medidor de segmentos preenchidos — uma leitura visual rápida do nível de leitura/escrita/admin.
acessoA palavra da permissão: leitura, escrita, criar repositório, ou admin.
origemdireto, grupo, ou grp:<nome> para uma concessão derivada de associação a um grupo; com o prefixo ↳ para uma concessão em nível de Projeto.
usuárioO nome de exibição do principal.
desde a basePara uma linha alterada, a transição "de → para" (por exemplo, leitura → admin).
notasEtiquetas: escalonamento / escalonamento → admin, membros não resolvidos (veja abaixo), ou etiquetas de edição pendente.

membros não resolvidos aparece na própria linha de um grupo quando a permissão do grupo foi buscada com sucesso, mas sua lista de membros não pôde ser obtida (geralmente por causa de um escopo faltando na senha de aplicativo) — nesse caso, nenhuma linha individual de membro é exibida para aquele grupo, já que não há como saber quem eles são.

Nota sobre "criar repositório". O Bitbucket tem um quarto nível de acesso, que só se aplica em nível de Projeto, ficando entre escrita e admin. Ele sempre aparece com seu próprio nome onde quer que seja exibido, mas, para contar alterações e sinalizar escalonamentos, o dashboard o trata como equivalente a admin — então alternar alguém entre criar repositório e admin nunca é sinalizado como uma mudança.

Comparando duas execuções

A barra superior tem dois seletores, base e comparação, cada um listando todas as execuções registradas por número e data (a execução 1 é sempre a primeiríssima execução já feita). Altere qualquer um dos seletores para mudar o que está sendo comparado; use o botão ⇄ para trocá-los de lugar.

É permitido selecionar a mesma execução para os dois — isso apenas mostra o roster dessa execução sem marcadores de diferença, o que é uma forma normal de navegar pelo acesso atual sem comparar com o histórico.

Ao lado dos seletores, uma nota como 14 dias de distância · 82 → 91 concessões (ou execução única · 82 → 82 concessões quando os dois lados coincidem) dá uma noção rápida de escala, e uma fileira de chips à direita resume a diferença: +3 adicionadas −1 revogada ~2 alteradas mais um chip separado ↑N escalonadas quando alguma mudança de nível subiu. Se nada mudou, um único chip sem alteração aparece em vez disso.

Filtrando e expandindo

A barra logo abaixo do cabeçalho oferece duas abas:

  • Todo o acesso — toda concessão no snapshot de Comparação, alterada ou não.
  • Somente alterações — apenas as linhas que diferem da Base; repositórios sem nenhuma alteração desaparecem completamente da lista.

Ao lado das abas: uma contagem em tempo real (N ativos · N alterados · N linhas), um alternador Expandir tudo / Recolher tudo (seu rótulo sempre reflete o que o clique vai fazer, restrito ao que está visível na aba ativa), e Redefinir, que volta para a aba Todo o acesso e limpa toda expansão/recolhimento manual que você tenha feito.

Se um filtro não deixar nada para mostrar, uma mensagem explica o motivo — seja "nenhuma alteração de permissão entre a execução X e a execução Y" (com um botão para mudar para Todo o acesso), seja um genérico "nada corresponde a estes filtros" (com um botão para redefinir).

Alterando ou removendo acesso

A partir do roster do snapshot de Comparação — mas somente enquanto esse snapshot for o mais recente já registrado — você pode editar o acesso diretamente pelo dashboard, sem precisar ir ao Bitbucket.

A edição só está disponível quando a Comparação que você está vendo é o snapshot mais recente. Se você escolheu uma execução mais antiga para comparar, os menus de linha (⋯) simplesmente não aparecem — editar em cima de uma visão histórica seria mudar o presente com base em um retrato do passado.

O que pode ser editado

  • Qualquer concessão Direta (a permissão de uma pessoa específica) — em nível de repositório ou de Projeto.
  • Qualquer concessão de Grupo (a permissão do próprio grupo) — em nível de repositório ou de Projeto.
  • Linhas de Membro (acesso derivado de associação a um grupo) não têm menu de edição algum — para alterá-las, edite a concessão do grupo correspondente.

Conceder acesso a alguém que atualmente não tem nenhum ainda não é suportado — a edição cobre apenas alterar ou remover uma concessão já existente.

Preparando uma alteração

  1. Clique no menu ⋯ à direita de uma linha.
  2. Escolha um novo nível (Leitura / Escrita / Admin) para preparar uma mudança de nível, ou ✕ Remover acesso para preparar uma remoção. Selecionar novamente o nível atual da linha cancela a edição preparada, em vez de não fazer nada.
  3. Se você estiver removendo a concessão de um grupo, o menu avisa quantas pessoas têm acesso derivado dele e também o perderiam (por exemplo, "remover isto também retira o acesso de 3 membros") — o acesso derivado de grupo (Membro) não tem um interruptor próprio, então remover a concessão do grupo remove tudo de uma vez.

Linhas preparadas são marcadas como pendente · não salvo ou remoção pendente e mostram uma prévia da alteração imediatamente (com texto riscado no caso de uma remoção). Nada é enviado ao Bitbucket ainda. Clique em ↺ desfazer em uma linha preparada para descartar apenas aquela alteração.

Você pode preparar quantas alterações quiser em diferentes repositórios antes de aplicar qualquer coisa.

Aplicando

Assim que ao menos uma alteração estiver preparada, um botão Aplicar N alterações aparece na barra superior. Ao clicar, abre-se uma caixa de confirmação listando cada alteração preparada (repositório, pessoa, nível de → para, e qualquer aviso de cascata), para uma última revisão antes que algo aconteça de fato.

Clique em Confirmar para enviar o lote inteiro ao Bitbucket. Cada alteração é aplicada de forma independente — se uma falhar (por exemplo, escopo de credencial insuficiente, a concessão já ter sido alterada em outro lugar, ou limitação de taxa), isso não bloqueia o restante do lote. A tela de resultados mostra um status ✓/✕ por linha, com o motivo de qualquer falha:

FalhaSignificado
credencial sem o escopo necessárioSua senha de aplicativo não tem direitos de admin naquele repositório/Projeto.
limitado por taxa — tente novamenteO Bitbucket restringiu a requisição; tente aplicar de novo em instantes.
(outra mensagem)O erro exato retornado pelo Bitbucket.

O que falhar continua preparado no dashboard para você tentar novamente mais tarde; o que tiver sucesso é removido da lista de pendências.

Aplicar altera as permissões ativas do Bitbucket — não altera o snapshot que você está vendo. Um snapshot nunca se atualiza sozinho; o dashboard continuará mostrando os números antigos até você fazer uma nova Execução ou Atualização (abaixo).

Qualquer edição preparada mas ainda não aplicada é descartada silenciosamente (não é levada adiante) se uma nova Execução ou Atualização terminar, ou se você trocar a Comparação para outro snapshot — de qualquer forma, o snapshot contra o qual elas foram preparadas deixou de ser o que está na tela.

Atualizando após uma alteração

Logo depois de aplicar um lote (na tela de resultados), se ao menos uma edição tiver dado certo, um botão Atualizar afetados aparece. Essa é uma forma rápida de ver suas edições refletidas sem uma Execução completa:

  • Cria um novo snapshot copiando todo repositório/Projeto não tocado pelo seu lote diretamente do snapshot em que você editou.
  • Busca dados atualizados apenas dos repositórios específicos (ou, no caso de uma edição em nível de Projeto, de todo repositório daquele Projeto) que suas edições bem-sucedidas afetaram.
  • Não redescobre o workspace — se um repositório foi criado, excluído ou movido entre Projetos desde sua última Execução, apenas uma Execução completa vai perceber isso.

Em caso de sucesso, a caixa de diálogo se fecha, as edições pendentes restantes são limpas, e o novo snapshot é automaticamente selecionado como a Comparação (sua seleção de Base permanece intacta).

Fechar a tela de resultados em vez de atualizar encerra essa oportunidade — você precisaria de uma Execução completa para ver a alteração refletida depois.

Exportando um roster em CSV

Clique em Exportar na barra de filtros para salvar um arquivo CSV com o roster completo do snapshot de Comparação atual.

  • Sempre apenas o snapshot de Comparação — nunca uma diferença, e não é afetado pela Base ou pelos filtros de visualização ativos na tela no momento.
  • Uma linha por concessão: projeto do repositório, repositório, id do principal, nome de exibição, tipo de acesso (direto / grupo / member:<grupo>), nível (repo / project), nível de permissão, e a data/hora da execução.
  • Você será solicitado com uma caixa de diálogo nativa para salvar; o nome de arquivo sugerido é roster_<workspace>_<timestamp>.csv.

Isso é pensado para um compartilhamento ou arquivamento pontual — o dashboard em si continua sendo a fonte da verdade para auditoria contínua, não o CSV.

Gerenciando snapshots

O painel de snapshots, no painel de configurações, lista todas as execuções já registradas, da mais recente para a mais antiga. Clique em Excluir ao lado de uma delas e depois em Confirmar para removê-la permanentemente (ou Cancelar para desistir).

Excluir um snapshot é permanente. Se você excluir o snapshot atualmente selecionado como Base ou Comparação, o dashboard volta a comparar a execução mais recente restante com a anterior a ela — o mesmo padrão usado no primeiro carregamento.

Aparência

O painel de aparência, no painel de configurações, alterna entre os temas Claro e Escuro. A escolha se aplica imediatamente e persiste entre sessões.

Perguntas frequentes

Nada acontece quando clico em "Obter todos os dados"

Verifique se as credenciais estão salvas (o painel de credenciais deve mostrar "conectado como ... em ..."). Se uma Execução falhar de cara com um erro, o mais provável é que o Bitbucket tenha rejeitado a própria credencial (por exemplo, senha errada, ou a senha de aplicativo sem o escopo básico de leitura do workspace) — nesse caso, nenhum snapshot é salvo.

Um repositório mostra "falha na busca" — meus dados estão errados?

Não — uma falha na busca significa que a ferramenta ainda não sabe as permissões daquele repositório nesta Execução; isso é rastreado separadamente de "este repositório realmente não tem concessão nenhuma". Executar novamente (ou atualizar, se a falha for em um repositório editado) tentará a busca de novo.

Por que não consigo editar permissões em um snapshot que estou visualizando?

A edição só é oferecida quando o snapshot de Comparação é o mais recente registrado. Selecione a execução mais nova como sua Comparação para ter os menus de edição de volta.

Por que não vejo nenhuma linha de membro sob este grupo?

Ou o grupo realmente não tem membros, ou sua composição não pôde ser buscada (geralmente uma limitação de escopo na senha de aplicativo) — nesse último caso, a linha é marcada com membros não resolvidos e nenhuma linha de membro é exibida, já que a ferramenta não tem como saber quem eles seriam.

Apliquei uma edição e o dashboard ainda mostra a permissão antiga

Isso é esperado — aplicar envia a alteração ao Bitbucket, mas um snapshot é imutável e nunca se atualiza sozinho. Use Atualizar afetados na tela de resultados da aplicação, ou faça uma nova Execução completa, para ver a alteração refletida.

Minha aplicação falhou com "credencial sem o escopo necessário"

Alterar ou remover acesso exige alguns escopos extras no seu API token do Bitbucket, além do que já é necessário para apenas visualizar — veja Criando um API token do Bitbucket. Adicione os escopos que faltam ao seu token no Bitbucket, salve o token atualizado no painel de credenciais, e tente de novo — a edição que falhou continua preparada para você.

Posso auditar mais de um workspace do Bitbucket?

Não — um workspace configurado por vez. Trocar de workspace significa mudar o campo de workspace no painel de credenciais e fazer uma nova Execução.

Isso está conectado a alguma notificação ou alerta?

Não. É uma ferramenta que você mesmo consulta ativamente — você abre e compara execuções por conta própria; nada envia alertas para você.

Glossário

Principal
Um usuário ou um grupo que pode ter uma concessão de permissão.
Nível de concessão (Repositório / Projeto)
Se uma concessão vive no próprio repositório, ou no seu Projeto (cascateando para todo repositório que o Projeto possui).
Concessão direta
Uma permissão atribuída a uma pessoa individualmente.
Concessão de grupo
Uma permissão atribuída a um grupo como entidade própria.
Concessão de membro
Uma permissão que uma pessoa tem por pertencer a um grupo com uma concessão de grupo; não editável separadamente.
Execução
Uma varredura completa do workspace (redescobre todo repositório/Projeto) que produz um novo snapshot.
Atualização
Uma busca restrita apenas aos repositórios/Projetos afetados por um lote de edições recém-aplicado; produz um novo snapshot, mas nunca redescobre o workspace.
Snapshot
Os dados de uma Execução ou Atualização, imutáveis e com data/hora, referentes a todo o workspace.
Base / Comparação
O snapshot mais antigo ("como era") e o mais novo ("como está agora") do par sendo comparado.
Concessão / Revogação
Acesso que aparece / desaparece entre a Base e a Comparação.
Escalonamento / Rebaixamento
O nível de uma concessão subindo / descendo entre a Base e a Comparação.
Edição pendente
Uma alteração preparada, ainda não aplicada, em uma concessão Direta ou de Grupo, mantida localmente até você clicar em Aplicar.
Aplicar
Enviar toda edição atualmente preparada ao Bitbucket como alterações reais de permissão.
Associação não resolvida
Um grupo cuja própria concessão foi buscada, mas cuja lista de membros não pôde ser; nenhuma linha de Membro é derivada dele naquela Execução.
